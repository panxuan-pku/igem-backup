# iGEM 架构规划：VirtualCellTool v1/v2 与项目主线的整合

> 对应评审三大支柱：Engineering（DBTL）、Contributions（工具改进）、Attributions（归属）

## 1. 双模型架构总览

```
                    【项目主线：RNA binder 调控翻译 → AAV 递送 → CNS 疾病】
                                      │
        ┌─────────────────────────────┼─────────────────────────────┐
        ▼                                                             ▼
  【v1: 归因筛选层】                                        【v2: 因果预测层】
  VirtualCellTool (现有)                                    GEARS/scGen 虚拟细胞
  · 输入: 疾病 scRNA-seq                                    · 输入: v1 的候选靶基因
  · 输出: 候选靶基因清单                                     · 输出: 扰动后全转录组预测
  · 角色: "改哪个基因"                                       · 角色: "改了会怎样"
  · 证据级别: 方向性/相关性                                   · 证据级别: 因果近似
```

**两层的接口**：v1 差异归因产出的 top N 候选基因 → 作为 v2 的扰动输入；v2 预测结果 → 反哺主线 RNA binder 的靶点最终确认。

## 2. 与项目主线的三个接口

| 接口 | v1/v2 输出 | 主线用途 |
|---|---|---|
| ① 靶点发现 | 差异归因候选基因清单（MS 数据已产出） | 选择 RNA binder 调控的目标基因 |
| ② 安全论证 | 候选基因在 22M 细胞/各组织的重要性分布 | AAV 脱靶安全窗口（Slide 12 任务） |
| ③ 效果预览 | v2 预测的扰动后细胞状态 | 湿实验前的 in silico 概念验证 |

## 3. DBTL 全景（Engineering 页面结构）

- 循环 1（✅完成）：反事实扰动核心机制 — AC1/AC2 通过，p<0.0005
- 循环 2（✅完成）：工具化与可用性 — AC3 通过；3 次真实 UI 迭代（基因搜索/可点击表/输入防护）
- 循环 3（✅完成）：多基因扰动 — **负结果**：12 基因敲低不翻转细胞类型 → 定位局限根源（无因果训练）
- 循环 4（进行中）：真实疾病数据（MS 少突胶质细胞）差异归因 → 候选靶点
- 循环 5（规划）：v2 接入 GEARS — 用循环 3 的负结果作为动机论证

## 4. v1 vs v2 的分工论证（避免评审质疑"为什么不直接用 GEARS"）

| 维度 | v1 (SCimilarity 反事实) | v2 (GEARS 因果) |
|---|---|---|
| 训练数据 | 23M 真实细胞（无扰动） | Perturb-seq 扰动实验 |
| 速度 | 秒级/细胞 | 分钟级 |
| 适用问题 | 哪个基因重要（排序） | 改了会怎样（预测） |
| 泛化 | 任意细胞类型 | 受 Perturb-seq 细胞系限制 |
| iGEM 定位 | **demo/筛选工具**（评委可交互） | **深度分析引擎**（后端批处理） |

**叙事要点**：两层不是竞争而是流水线——v1 快速筛选值得深研的靶点，v2 对少数候选做因果验证。负结果（循环 3）是分层必要性的直接证据。

## 5. Contributions 落点（最终 1-2 个工具）

**主贡献**：VirtualCellTool 交互式归因扰动平台（现有 + MS 真实数据模块）
- 原工具不具备的功能：交互式扰动、多基因联合敲低、类型重判、差异归因管线
- 对未来队伍的价值：任何"基因表达调控类"项目的靶点初筛 + 演示

**次贡献（可选）**：v1→v2 桥接模块（差异归因输出 → GEARS 输入的标准化接口）
