1. 先看这些

  • 当前工具与主效基因排名管线独立，尚未自动串联；WS 是 Williams/WBS，不是 WHS。
  • 从仓库根运行 bash scripts/setup_envs.sh；随后 cd 05_virtual_cell，并用 ../.venv/vct/bin/python web/app.py 启动。浏览器打开 http://127.0.0.1:8377/。
  • PBMC 用于工具可行性测试；MS/WS 中患者与对照的标签不能当成已确认的细胞类型。CIPHER 是线性近似，嵌入位移不证明治疗效果。
  • 运行资源位于 data/、gears_ckpt/ 和兄弟 SIGnature/model_files/；标签、编码、表达和基因顺序需要配套保留。
  • 历史设计在 docs/，历史图表在 data/ 和 outputs/figures/；网页历史面板仍读取这些路径。
  • 早期 check_gears_genes.py 有缺少 sys 导入和未定义 ROOT 的问题。当前 API 仅替代其中的训练图覆盖查询，不能完整替代直接扰动集合比较，因此标记陈旧保留，不作为操作入口。
  • prepare_ws_umap_v2.py 等历史准备脚本会覆盖既有结果，再运行前应核对输入和输出；本次没有运行或改写它们。
  • 离线回归使用 ../.venv/vct/bin/python -m unittest discover -s tests -v；在线与浏览器验收前先读原 README 的端口和数据要求。

VirtualCellTool

cd 05_virtual_cell

数据与测试

SIGnature / SCimilarity 输入与输出约定

这套模型用于细胞编码、基因归因和实验性编码器敏感性探索，不是 03_pipeline 每次筛选疾病时自动运行的步骤，也不是 CIPHER / GEARS 的共同扰动引擎。表达来自输入单细胞数据；embedding 和归因才是模型计算结果。

本项目 Python 入口 输入结构 输出结构
PerturbEngine.embed(X) 稠密 NumPy 数组 (n, G)，n >= 1 当前模型为 (n, 128) embedding
perturb(x, gene, new_value) / perturb_multi(x, gene_values) 单细胞数组 (G,)；基因名及新表达值，多基因时为字典 修改前后 embedding、差值及位移
batch_perturb(X, gene, new_value) 数组 (n, G)，同一基因/数值作用于整批 修改后的 (n, 128) embedding
AttributionEngine.attribute(x) / top_genes(x) 单细胞数组 (G,) (G,) IG 归因 / 排序后的基因、归因与表达值
  • 基因列：G 以实际加载的 wrapper.gene_order 为准，当前为 28,231；每列必须严格按该顺序对应基因，不能按字母重排或直接传 HVG 子集。data/gene_order.txt 应与模型顺序一致。归因矩阵列顺序也按此定义，排序后的差异表不能代替它。
  • 表达尺度：传入已经按模型基因空间对齐、经 lognorm_counts 处理的表达，不是原始 counts、差异表达、归因分数或 embedding。基因标识转换、对齐和归一化由数据准备步骤负责，推理入口不自动猜测、补列、转置或归一化。
  • 基本校验：拒绝错误维度/宽度、空批次、列表和稀疏矩阵，以及字符串、object、布尔、复数、NaN/Inf 和超出 float32 范围的值；在调用上游模型前抛出 ValueError。实数数组按模型原有 float32 精度计算，不修改调用者数组；整数数组也会转换，避免小数扰动值被截断。类型可接受不代表原始计数可以直接推理。
  • 扰动参数：基因必须在模型基因表中，三个扰动入口统一明确报错；替换值必须是有限且在 float32 范围内的实数标量，尺度与输入一致，不接受字符串或单元素列表。
  • 校验边界：只凭无标签数组无法检查基因顺序是否真实正确、样本身份或归一化是否合理；这些仍由准备步骤和使用者核对。本项不是科学有效性检查，也没有新增整机内存预算或自动稠密化。

五、CIPHER 引擎原理

拟合阶段（每数据集一次，缓存到磁盘）:
┌──────────────────────────────────────────────────┐
│  对照细胞 X[n_cells × n_genes]  ← CSR 稀疏，不稠密化 │
│      │                                              │
│      ▼ 稀疏逐列方差 → 选 Top 5000 HVG（方差最大）      │
│  X_hvg[n_cells × 5000]  （仅此处稠密化，~2GB 上限）    │
│      │                                              │
│      ▼ 算基因-基因协方差 + 岭正则化                    │
│  Σ = (Xcᵀ Xc)/(n-1) + λ·diag_mean·I                │
│      │                                              │
│      ▼ 存盘: cipher_{ds}.npz                         │
│        含 gene_list / ctrl_mean / Sigma /            │
│           hvg_idx / full_mean  ← 缺任一项会失效重算   │
└──────────────────────────────────────────────────┘

预测阶段（每次 0.02–0.1s）:
┌──────────────────────────────────────────────────┐
│  输入: gene=MS4A1, direction=ko                    │
│      │                                              │
│      ▼ 构建扰动向量 u                                │
│  u[MS4A1_idx] = 0 - ctrl_mean[MS4A1]  (敲低→0)     │
│      │                                              │
│      ▼ 线性响应                                     │
│  Δx = Σ @ u      (5000 维向量)                      │
│      │                                              │
│      ▼ 排序 |Δx| → Top 30 基因                       │
│      ▼ 分组响应 = 余弦对齐度（类型特异谱 vs |Δx|）      │
│      ▼ 输出                                         │
└──────────────────────────────────────────────────┘

分组响应公式（v3.1 方法学修复，判别力 2/12 → 10/12）：

w_ct[g] = max(0, expr_ct[g] − mean_over_celltypes[g])   # 类型特异富集量
response = Σ w_ct[g]·|Δ[g]| / (‖w_ct‖·‖|Δ|‖)            # 余弦对齐度

基因筛选方案 · 三轮迭代设计评审记录

评审对象：SIGnature（SCimilarity 归因）+ GEARS（因果扰动）的”双向验证”基因筛选方案 评审方法：每轮 = 以 iGEM 评委视角提问 → 以团队身份诚实自答 → 定位缺口 → 应用修改。连续三轮。 对应代码：src/v2_closed_loop.py（v1→v2 闭环）、src/compute_ms_attribution.py（v1 归因）

评审前状态（v2.0）

v2_closed_loop.py 用 CEBPA 验证 GEARS 加载/基因顺序正确（pearson r=0.972），并据此声称 “位移 0.338 是 v1 单基因扰动 0.01 的 34 倍，证明 v1 无级联效应、需要 v2 补足”。 本记录证明该结论不成立，并给出修正架构。

第 1 轮：方案定义与数据流

1.1 评委提问

  • Q1：“双向验证”到底验证什么？谁是”筛”、谁是”验”、结论对象是谁？v2 的输出有没有反哺去修正 v1 的排序？
  • Q2：闭环在真实疾病候选基因上闭合了吗？v1 筛出 FTL/ASPA，但 GEARS 只认 Norman 扰动图（K562 转录因子），FTL/ASPA 不在 pert_list。跑通的 CEBPA 与 MS 少突胶质零关系。
  • Q3：用 K562 的因果模型去”验证”CNS 细胞的归因，生物学前提是什么？
  • Q4：0.338（v2，K562）vs 0.01（v1，B 细胞）是同一把尺子吗？

1.2 团队自答（暴露的缺口）

  • G1：没有真正双向验证——v2 只证明了 GEARS 加载正确，没验证归因方案。
  • G2：数据流断点——疾病候选基因喂不进 GEARS，闭环未闭合。
  • G3：跨域无前提，K562→CNS 因果迁移不成立。
  • G4：尺度不可比，“34 倍”论证作废。

1.3 本轮修改

  • M1：确立两层架构——Tier 0 方法验证层（Norman/K562，有因果 ground truth）+ Tier 1 应用层（MS，无 ground truth）。
  • M2：重新定义”双向”= 正向（precision）+ 反向（recall）两个可证伪检验，都在 Tier 0 内做。
  • M3：GEARS 职责改为”验证方法”，不验证具体疾病基因。
  • M4：CEBPA 降级为反向检验的一个数据点，不再是整个 demo。

1.4 修改后状态

架构：单链 demo → 验证层 + 应用层。 缺口消除映射：G1→M2，G2→M3，G3/G4→M1（不再跨域比较）。

第 2 轮：Tier 0 验证的严谨性

2.1 评委提问

  • Q1（混淆变量）：attribution 和 perturbation effect 都跟基因表达水平相关。你证明的会不会只是”高表达基因扰动效应大”？SIGnature 的核心论点就是”表达量 ≠ 重要性”，你的验证必须直接检验这一点——加表达量/随机基线，证明归因有增量预测力。
  • Q2（统计功效）：Norman 有多少单基因扰动有真实敲低细胞？n 是多少？Spearman 相关够不够？
  • Q3（recall 定义）：“效应大”的阈值、recall@K 的 K 取多少？阈值选择会左右结论，需要敏感性分析。
  • Q4（方向 vs 幅度）：归因有符号，效应是恒正位移。正向检验用 |attr| 还是带符号？符号与效应方向是否单独检验？

2.2 团队自答

  • G5：缺少基线对照，相关性可能被表达水平混淆。
  • G6：n 未统计，功效未知。
  • G7：recall 阈值未定义。
  • G8：符号信息未纳入。

2.3 本轮修改

  • M5：正向检验加三个基线——表达量 rank、随机 rank、以及归因对表达量的增量预测力（partial correlation / 含表达量协变量的多元回归）。
  • M6：明确 n = Norman 有真实敲低细胞的单基因扰动数（以实际数据统计为准，预计约百来个），据此报功效。
  • M7：recall@K 取 K∈{10,20,50} 做敏感性；“效应大”定义为真实位移 top-10%。
  • M8：正向检验用 |attr|（幅度）；另设符号对齐检验（attr 符号 vs 敲低效应方向一致性）。

2.4 修改后状态

Tier 0 从”算一个相关系数”升级为”带基线的可证伪检验套件”。

三轮后的最终架构（v2.1）

Tier 0 — 方法验证（Norman/K562，有因果 ground truth）

  1. 对照细胞 → SCimilarity embedding + IG 归因（28,231 空间，3536/5045 基因可映射）
  2. 对每个有真实敲低细胞的单基因扰动 g，算真实因果效应 = ‖embed(KD cells) − embed(ctrl)‖（GEARS 预测效应作补充）
  3. 正向（precision）：Spearman(attr_rank, effect) + 表达量/随机基线 + partial correlation
  4. 反向（recall）：recall@K（K=10/20/50）+ AUROC（top 效应基因 vs 随机）
  5. 符号对齐：attr 符号 vs 敲低效应方向
  6. 产出可引用数字：r、p、recall、AUROC

Tier 1 — 应用（MS 少突胶质，无 ground truth）

  1. 归因 → 差异归因（Cohen’s d）→ 排序清单
  2. 外部验证：MS GWAS/文献已知基因富集（次级证据）
  3. 输出规格：CSV + 置信声明

假设清单（显式）

  • H1（Tier 0 内可检验）：K562 上归因排序与真实因果扰动效应显著相关，且增量于表达量。
  • H2（迁移，弱）：该相关关系可迁移到其他细胞类型（方法迁移，非逐基因迁移）。
  • A3（局限）：转录层面重要性对翻译层面干预只有参考价值。

诚实 gap（评委追问的标准回答）

  • Tier 0 验证的是方法，不是 FTL/ASPA 这两个具体基因。
  • FTL/ASPA 的因果验证三路（从强到弱）：① 湿实验 CRISPRi 敲低少突胶质；② CNS Perturb-seq 重训 GEARS；③ CellOracle/SCENIC 在 MS 数据上做同域 in silico 敲低（无 ground truth 的次级证据）。
  • 标准话术：“我们在 K562 上证明了归因排序与因果扰动效应显著相关（r=?, recall=?），因此把归因作为疾病数据里的筛选器；FTL/ASPA 的最终因果验证留给湿实验。”

  2. 统计 Norman 单基因扰动 n 与真实细胞数（确定功效）。

Tier 0 实测结果（2026-08-16，负结果）

src/tier0_validate.py 在 Norman/A549 上跑通（注意：cell_type 实为 A549 非 K562）。 n=101 个单基因敲低（映射进 SCimilarity 且有真实细胞），效应测量无 n_cells 混杂（r=0.028）。

指标 值 结论
Spearman(归因, 真实效应) 0.022 (p=0.83) 不相关 → H1 被证伪
Spearman(表达量, 真实效应) -0.092 (p=0.36) 不相关
Spearman(随机, 真实效应) 0.007 ± 0.093 零基线
Spearman(归因, 表达量) 0.862 此数据归因≈表达量
partial Spearman(归因, 效应 | 表达量) 0.176 (p=0.079) 弱、不显著
recall@10/20/50 0.2 / 0.2 / 0.56 接近随机
AUROC(top10% 效应) 0.56 接近 0.5

结论： 1. “双向验证”假设 H1（归因≈因果重要性）被证伪，原”GEARS 验证归因”思路作废。 2. 此数据里归因≈表达量（r=0.86），与 SIGnature 论文”表达量≠重要性”头条口号在秩相关层面相悖（他们强调的是顶部几个基因不同，整体排序仍跟表达量走）。 3. 负结果与 v1 负结果（12 基因敲低不翻转类型）同源：细胞身份冗余度高 → “表征重要性” ≠ “非冗余必需性”。

修正叙事：归因=表征重要性筛选器（marker 恢复 + 文献/GWAS 富集验证，非因果）；GEARS=因果预测器（held-out 验证 r=0.972，域受限）。两者互补非互验，r=0.02 即”重要≠必需”的直接证据。

工程文档 — VirtualCellTool

对应 iGEM Engineering 评审要求：DBTL 循环 + 假设清单 + 验收标准。

1. 问题陈述（Problem）

iGEM 队伍设计”改变基因表达”的干预方案时，缺乏低成本手段在湿实验之前预览干预对细胞状态的影响。现有工具（SIGnature 等）只做静态分析，无交互式扰动模拟。

2. 文献基线与已知限制

  • SIGnature (Nat Biotechnol 2026)：attribution 排序基因重要性，但无扰动模拟、无交互界面
  • SCimilarity (Nature 2024)：编码器可对反事实输入做前向推理（原论文做过 in silico perturbation）
  • scGen / CPA / GEARS / scDiffusion：基于 Perturb-seq 训练的因果扰动模型（我们的 v2 升级路径）

3. 假设、近似与简化（Assumptions）

  • A1：编码器对小幅度反事实扰动的响应方向具有生物学参考价值（外推可靠性随扰动幅度衰减）
  • A2：转录组 embedding 位移可近似代表细胞功能状态变化
  • A3：转录层面证据可外推至翻译层面干预（与本队 RNA binder 机制的层面差异，定位为概念验证）
  • S1：demo 阶段仅用 PBMC 数据集（非疾病模型），验证方法论而非具体疾病结论

4. 验收标准（Acceptance Criteria）

编号 标准 测量方法 阈值
AC1 方向性：敲低细胞类型标志基因后，细胞 embedding 远离其类型质心 位移向量 vs “细胞→质心”向量的余弦相似度，对比随机基因基线 显著大于随机基线，置换检验 p<0.05
AC2 区分度：标志基因扰动的位移幅度 > 等量随机基因 位移 L2 范数对比 效应量显著（p<0.05）
AC3 可用性：滑块操作→UMAP 更新延迟 计时 < 2 秒
AC4 可复现：新机器 30 分钟复现 demo README 一键脚本 通过

5. DBTL 循环记录

循环 1：核心机制验证

  • Design: 反事实扰动走 SCimilarity 编码器 + AC1/AC2
  • Build: src/perturb.py
  • Test: PBMC 数据 + 置换检验
  • Learn:
    • 失败记录 1：SIGnature lognorm_counts() 要求原始 counts 存于 layers['counts']，直接传入 X 为原始 counts 的 AnnData 会报错 → 修复：显式 adata.layers['counts'] = adata.X.copy()
    • 失败记录 2：scanpy leiden 聚类缺 igraph/leidenalg 依赖（SIGnature 未声明）→ 补装
    • 成功结果（data/validation_results.json）：AC1 方向性 +0.0012 vs 随机 -0.0000（p<0.0005）；AC2 位移幅度 0.0124 vs 随机 0.0007（~18x，p<0.0005）→ 核心假设 A1 在小扰动范围内成立
    • 生物学 sanity check：B 细胞 attribution top = MS4A1/CD79A/BANK1，与 SIGnature 原论文 Fig.2 结论一致

  • Design: 假设”联合敲低 top N 身份证基因可使细胞类型重判翻转”
  • Build: perturb_multi + 最近质心分类器 + Top1/3/5 按钮
  • Test: B 细胞 #1，分别敲低 Top1/3/5/8/12 基因
  • Learn:

    • Sanity check 通过：PLP1（髓鞘主蛋白）为两组 |attribution| 第一名；MOG 重要性在 MS 中减半（0.0007 vs 0.0015），与脱髓鞘生物学一致
    • 产出：data/ms_differential_attribution.csv（全基因差异归因表）+ ms_analysis_report.png
    • 候选基因（|d|>0.3）：MS 中重要性↑ = ACTB/FTL（铁代谢）/LRP2 等；MS 中重要性↓ = ASPA（少突胶质标志）/NCAM1/CTNNA3 等

循环 5：v2 因果扰动模型接入 + 闭环验证（成功）

  • Build: src/v2_closed_loop.py
  • Test: CEBPA 敲低（Norman 数据集中有 70 个真实敲低细胞做对照）
  • 过程中的失败记录：

方法学修复（图表有判别力）

问题：细胞类型响应排序几乎没有区分度——MS4A1（B 细胞标志物）敲低时 B 细胞只排第 3，与第 1 名差距 <5%。

根因：旧公式 = 「该类型 Top500 高表达基因上的 |Δ| 均值」。但各细胞类型的最高表达基因几乎都是核糖体/管家基因、彼此高度重叠，所以所有类型得分几乎相同。

修复：改为类型特异谱 vs 扰动效应谱的余弦相似度

w_ct[g] = max(0, expr_ct[g] - mean_over_celltypes[g])     # 该类型特异富集量
response = Σ w_ct[g]·|Δ[g]| / (‖w_ct‖·‖|Δ|‖)              # 余弦对齐度

两个关键细节： - 基准用各类型均值的均值，不是全体细胞均值——否则最大的细胞群（PBMC 里 T 细胞占 45%）会把基准拉向自己，导致它在任何扰动下都排不上去。 - 用余弦而非加权均值——消除两侧幅度影响，否则本身高表达的类型（单核细胞 LYZ/S100A9）在任何扰动下都拿最高分。

实测效果（PBMC，12 个标志物基因敲低，看最敏感类型是否命中该基因的已知归属类型）：

方案 Top1 命中 平均排名
旧（Top500 均值） ~2/12 ~3.0/5
新（余弦对齐） 10/12 1.33/5

命中：MS4A1/CD79A/CD79B→B cell、IL7R→T cell、LYZ/CD14/S100A9→Monocyte、GNLY/NKG7→NK cell、FCER1A→Dendritic 未命中：CD3D、CD3E（→Dendritic）。这是 CIPHER 线性响应的固有局限，不是代码 bug：这两个基因在 PBMC 中表达稀疏、协方差信号弱。汇报时应如实标注。

4.3 CIPHER 原理（核心新模块）

拟合：
  对照细胞 X[n×28231] → 选 Top5000 HVG → 算协方差 Σ[5000×5000]
  → 岭正则化 Σ += λ·diag_mean·I → 存盘 cipher_{ds}.npz

预测 (0.1s)：
  输入: gene, direction (ko=敲低→0, oe=过表达→2×ctrl)
  构建: u[gene_idx] = target - ctrl_mean
  计算: Δx = Σ @ u    （5000 维）
  排序: Top30 |Δx| → 分上调/下调

                    【项目主线：RNA binder 调控翻译 → AAV 递送 → CNS 疾病】
                                      │
        ┌─────────────────────────────┼─────────────────────────────┐
        ▼                                                             ▼
  【v1: 归因筛选层】                                        【v2: 因果预测层】
