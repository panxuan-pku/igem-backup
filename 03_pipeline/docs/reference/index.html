目的与边界

从病人单细胞 RNA-seq 数据中产出微缺失区间内的基因清单，作为 L1 遗传学管线（src/consensus*.py）的输入。

适用边界（重要）：

  • 缺失区间的权威来源是基因型（CNV 芯片 / WGS / MLPA / 临床报告）。表达型 CNV 推断（infercnvpy）只是没有基因型时的回退路径。
  • 胚系杂合微缺失（典型 1–3 Mb）处于表达型推断的分辨率极限：窗口平滑（25–100 基因）会稀释 25–60 基因的缺失信号，且稳态 mRNA 剂量补偿会进一步抹平信号（本项目 E8 已观察到”mRNA 隐身”）。自动发现的片段一律标记为探索性，必须正交验证。
  • 已知区间的基因提取不依赖表达信号；结果依赖输入坐标和基因注释的正确性，不替代临床确认。

仅输入缺失区间，不进行 CNV（2026-09-22 新增）

已获得临床确认区间，或本次只想按给定区间提取基因时，使用显式的 intervals-only 模式。不需要 samples、表达矩阵或自动分段；即使输出目录有旧 segments_all.csv、cnv_input.h5ad、热图，也不会读取或引用它们。保留旧文件，不把它们算作本次产物。

从 03_pipeline/ 运行：

../.venv/pipeline/bin/python -m src.cnv.workflow extract-genes \
  --config config/my_intervals.yaml --mode intervals-only

config/my_intervals.yaml 需自行创建，最小配置格式如下；chr1:100–200 仅为格式示例，不是疾病或临床区间：

project: my_study
annotation:
  gene_order_tsv: data/gencode_v44_gene_order.tsv
  genome_build: GRCh38
known_intervals:
  my_deletion:
    chr: chr1
    start: 100
    end: 200
    genome_build: GRCh38
extract:
  mode: intervals-only
output:
  dir: outputs_repro/my_intervals
  • 区间为 1-based、两端包含，起止必须是整数且 1 <= start <= end；支持 chr1～chr22、chrX/chrY 及不带 chr 的形式。注释和每个区间均需明确、匹配的 genome_build；不猜测版本、不自动 liftover。BED 等其他坐标体系需先转换，显式声明非 1-based-inclusive 会报错。声明一致不等于程序已核实文件真实组装版本。
  • 已有排序表即可提取；如果表缺失，可在 annotation 中额外指定 gtf，程序按原规则生成蛋白编码基因表并记录来源。基因与区间相交规则不变。
  • markers 可省略；CNV/表达两项验证为 NOT_EVALUATED 并附原因，不写成 FAIL，也不冒称 PASS。表达 QC 与自动片段基因表输出带表头空表。
  • include_auto_in_candidates: true 与仅区间模式冲突，会明确报错。不要使用 all 启动仅区间任务；all 会提示改用 extract-genes。缺省模式仍为 cnv，已有完整 CNV 命令不变。
  • 空区间配置或区间未命中基因时，候选 CSV 仍写入固定六列表头：gene_symbol,source,deletion_id,chrom,start,end。这表示成功得到零候选；后续 normalize 会按 CR-006 明确拒绝空候选，不能继续使用旧候选。

输出状态、历史与审计（CR-011/013）

prepare-order、infercnv、call-segments、extract-genes 各有独立 execution_id。audit/run_<stage>.json 表示该阶段最新状态；每次结束还保存 audit/records/<execution_id>.json，后续运行不覆盖这份记录。stage-samples 仍按 CR-010 做输入冲突预检，不属于这四个计算阶段的审计。

  • 记录完整配置快照、阶段有效参数、实际消费文件的真实路径/SHA-256、本次输出路径/SHA-256，以及上游执行编号和审计记录校验和。CLI 还记录配置文件校验和；命令行覆盖以有效参数和配置快照为准。输入、上游记录、输出以文件名或样本/文件名标识，路径单独保留。
  • 当前状态区分 running / success / failed；上游重跑时，依赖它的已有下游产物会归档，最新状态标为 invalidated。不依赖 CNV 的仅区间结果不会因 infercnv/call-segments 重跑而失效，但重建其基因注释时会失效。
  • 旧的阶段产物和最新审计移动到 history/<execution_id>/previous/；本次失败的半成品进入 incomplete/，失效的下游文件进入 invalidated_<stage>/。仅管理约定文件及前次审计记录的同类分辨率产物，不删除输入或未知文件，不自动清空 history。归档可能包含较大的 h5ad，需留意磁盘空间。
  • 必需的读取、计算或写入出错会使该阶段失败，不将已写出的候选半成品当成功结果。可选热图失败只警告，并在 infercnv 审计中记录 heatmap.status=failed 及原因；主表仍可成功，旧图和半张新图均不留作当前热图。
  • 复用 CNV 中间表时，检查上游成功状态、研究标识、对应阶段参数、文件路径/校验和、历史执行记录，以及 segments 与 h5ad 所属的 infercnv 执行。不同轮次或被替换的文件明确拒绝。仅调整下游分段阈值或待提取区间，可以复用兼容的上游。
  • 旧审计没有执行编号和校验链，不能自动冒认为已经验证；需要从相关上游重新运行。独立提供的 gene-order 表允许使用，会标记为 supplied_table 并哈希，不伪造 GTF 来源。历史仓库产物不会在此次代码修复中迁移。

边界：上述是串行执行下的产物管理，不提供并发写入锁或磁盘故障/进程中断时的事务回滚。异常终止可能留下 running，不能据此认为成功；多个研究应使用独立输出目录。

原始矩阵、身份与 QC 契约（2026-09-25）

  • 加载接受完整、同一压缩形式的 matrix.mtx[.gz]、barcodes.tsv[.gz] 和 features.tsv[.gz]（优先）或 genes.tsv[.gz]。矩阵方向必须是基因×细胞；只接收 Gene Expression，不能把归一化、负值、非有限值或非整数表达当原始计数。维度须与清单一致；重复矩阵坐标和不能被原有 float32 精确表示的计数明确拒绝。
  • 基因 ID、符号和样本内 barcode 不得缺失或带首尾空白；ID 和样本内 barcode 必须唯一。不同 ID 可以共用原始符号：矩阵索引 var_names 和 var.gene_ids 保存 ID，var.gene_symbols 保存原始符号，不求和、不加后缀。跨样本仍须有完全一致的 ID/符号及行顺序，不自动重排或补零。
  • 位置和表达 QC 按 gene_id 精确匹配；有 ID 的数据缺少注释 ID 时明确失败，不回退到符号。表达 QC 同时输出注释名称 gene_name、输入符号 gene_symbol 和 gene_id；窗口表的 genes 保留原始符号，另有 gene_ids。线粒体 QC 仍读取原始符号的 MT- 前缀。
  • gene_position_mapping.csv 逐行列出全部输入 ID、原始符号、注释名称、坐标和定位状态，纳入审计、归档和上游失效管理；h5ad 的 uns.gene_position_mapping 保留同表。not_in_supplied_annotation 表示未命中本次注释，不等于已证明基因不存在。CNV 仍只使用原有蛋白编码/主染色体注释中的可定位行；未定位编号显式列出，不补坐标。同一 ID 的冲突注释或无效位置明确报错。
  • 不同样本可重复使用同一 barcode。原值保存在 obs.barcode，细胞索引用 JSON [sample_id, barcode] 表示，另保留 obs.sample/group；消费者不要按旧索引分隔符拆解身份。原始计数保存在 layers['counts']。
  • 患者和对照类别须不同且都有样本/细胞。任一样本经原有 QC 后无细胞、没有可定位基因、没有可用 CNV 窗口，均报告数据不足并停止该阶段；不静默丢样本。注释中的同 ID 不同位置不能任取第一行；只有符号的旧内存对象也必须能无歧义匹配。QC 阈值、归一化、推断参数与评分方法不变。

infercnv.n_jobs 可限制推断并行进程数以降低内存峰值；省略时沿用 infercnvpy 默认值。该参数写入阶段追溯，计算分块、阈值、窗口及降采样设置不变。

CNV 验证状态（CR-012）

阶段是否执行成功与科学检验是否通过分别记录：

状态 含义
NOT_EVALUATED 对应步骤未执行，或显式仅区间模式；缺失测量值留空。
INSUFFICIENT_DATA 必要组/细胞/基因/窗口不足；区间没有推断窗口覆盖，或未配置 marker/区间基因不在表达数据中。
ERROR 读取或计算错误、上游失败/失效、已记录产物丢失；阶段失败，错误和分类写入审计，半成品归档。
PASS / FAIL 有可用数据并完成实际检验后，按原 overlap 阈值或 marker 检出规则判定；空的已完成片段调用可以为 FAIL。

异常阶段仍使用执行字段 status=failed，另加 validation_status=ERROR/INSUFFICIENT_DATA。成功提取的逐区间状态和原因写入 validation_known_intervals.csv、审计及报告。缺失文件有已执行记录时不能当作未执行；必须重跑对应上游。1 与 chr1 的染色体写法在 overlap 比较中等价，重叠比例公式和阈值不变。上述状态是工程表达，不把表达型阴性结果解释为无基因型缺失。

样本整理的重复运行与冲突处理

stage-samples 会先检查全部样本，再创建目录和文件；任一样本存在已知冲突，其他样本也不会先被整理。

  • samples 必须为非空列表，每项含唯一 id、group 和非空 path；id/group 必须为非空字符串且无首尾空白。样本目录按真实路径核对，符号链接不能绕过重复目录检查。infercnv 和直接 load_samples 也执行这些身份检查；无效配置在读取矩阵及改动已有计算产物前失败。仅区间提取不要求样本。
  • 原始 matrix/barcodes/genes 必须存在且是文件。目标三件套若已存在，只接受指向本次对应原始文件的符号链接（相对链接也可）；普通文件、错误/断裂链接和目录均报错，不覆盖。
  • 两列 genes 转为三列 features，三列及以上 genes 沿用直接链接；空基因表、列数不一致或不足两列、不可读压缩基因文件会报错，不猜测补齐。
  • 已有普通 features 按解压后的完整文本核对内容和顺序，正确则复用；已有 features 链接仅在原始 genes 可直接使用、且指向该原始文件时复用。缺失时才创建，生成文件使用排他写入，已有正确文件不会被重写。
  • 不同样本不得共用实际整理目录，也不能将一个样本目录放在另一样本预定输出文件的位置或其下方。错误消息给出冲突路径，CLI 非零退出；建议换用独立整理目录，或先人工核对并保存旧文件后再处理，不自动删除历史数据。

此预检确保样本身份字段有效、目录不重复和 features 与当前 genes 一致，不验证表达矩阵维度、计数合法性、患者/对照两组是否齐全或疾病真实性；也不检测同一路径原始矩阵被原地修改的历史版本变化。运行时请不要并发改动输入和目标目录；预检不是事务，预检后的磁盘/权限故障仍可能留下部分新文件，但不会报告成功。真实多样本 CNV 端到端验证另行执行。

方法学注意事项

  1. chrX/chrY 从自动发现中排除（exclude_chromosomes）：性染色体剂量差异会主导信号。已知区间在性染色体上时仍可提取基因，但不做表达型自动验证。
  2. 细胞组成混杂：patient 与 reference 的细胞类型比例差异会在表达信号上产生类 CNV 波动——这是自动片段假阳性的主要来源，也是”自动片段必须正交验证”的原因之一。
  3. 窗口重建有硬断言：window_table() 会校验重建的窗口数与 X_cnv 列数一致；infercnvpy 版本变更导致布局不匹配时会显式报错而非静默错位。
  4. 坐标版本必须一致：known_intervals.genome_build 与 GTF 必须同一版本。本例使用 GENCODE v44 并声明 GRCh38；原始 10x 矩阵的比对版本尚未独立核实，不能以成功匹配 ID 代替版本确认。
  5. 重复符号按唯一 ID 分别定位，保留各行计数及原始符号；不再使用 var_names_make_unique。未定位记录见 gene_position_mapping.csv，表达缺失见 QC 表 found。ID 对应也不能证明输入的参考基因组声明正确。

candidate_provenance.csv 保留每条提取记录，包括基因符号/编号、来源类型、区间 ID、基因坐标、链方向、参考基因组和输入区间坐标。chrom/start/end 是基因坐标，interval_chrom/interval_start/interval_end 是选择该基因的区间坐标；in_candidates 标识是否进入当前 candidates.csv，未启用自动候选时自动来源仍保留但标为 false。该明细纳入阶段审计、空结果表头、失败归档和上游失效管理。

正式候选无重复时保持原六列格式；两张探索表即使为空也含 gene_id。存在同一身份重复提取时，该表增加 candidate_provenance 列，每个单元格是该基因全部来源记录的 JSON 数组。不同来源合并后的 deletion_id 留空；source 若类型一致则保持原值，否则为 multiple。不能把空 deletion_id 解读为没有来源，应读取 JSON 或明细表。normalize.py 解析 gene_symbol 并透传 JSON，证据合并和最终排名 CSV 均保留；多次提取不增加评分权重。

此规则仅合并提取阶段已确认一致的身份。任意手工候选表或不同符号经 HGNC 映射后发生的重复，仍由下游原有唯一性校验拒绝，不自动推断别名关系或解决科学身份争议。

CNV 工作流详解：从 scRNA-seq 到候选基因

配套图：igem_cnv.workflow.html（Archify 交互式流程图，浏览器打开） 源文件：igem_cnv.workflow.json 本文对照图中 4 条泳道、11 个节点逐一讲解：先讲基础概念，再讲每一步”做什么 → 怎么做 → 为什么这么做”。

一、先搞懂三个基础概念

1. CNV 与微缺失：什么是”拷贝数变异”

正常人体细胞每条常染色体有 2 份拷贝（一份来自父亲、一份来自母亲）。CNV（Copy Number Variation，拷贝数变异）就是基因组上某一段 DNA 的拷贝数发生了变化：

  • 缺失（deletion）：2 份 → 1 份（杂合缺失）或 2 份 → 0 份（纯合缺失）
  • 重复（duplication）：2 份 → 3 份或更多

本项目关注的是 微缺失（microdeletion）：长度 1–3 Mb（百万碱基对）的小段缺失，典型例子就是 Williams 综合征（WBS）——7 号染色体 7q11.23 区域约 1.55 Mb 的杂合缺失，包含约 25–35 个蛋白编码基因。

为什么微缺失会致病？ 关键机制叫单倍剂量不足（haploinsufficiency）：某些基因必须要有 2 份拷贝才能产生足够的蛋白；只剩 1 份时蛋白量减半，功能就不够了。所以 iGEM 项目的核心问题是：缺失区间里有 30 多个基因，到底哪一个（或哪几个）是导致疾病的主效基因？ CNV 工作流的任务就是从这个区间里产出”候选基因清单”。

2. scRNA-seq：单细胞表达数据是什么样

scRNA-seq（单细胞 RNA 测序）测的是每个细胞里每个基因的表达量——即”哪个细胞表达了哪个基因、表达了多少”。

  • 普通 bulk RNA-seq：把一堆细胞磨碎混在一起测，得到平均值；
  • scRNA-seq：每个细胞单独测，得到一张 细胞 × 基因的矩阵（每行一个细胞，每列一个基因，数值 = 该基因在该细胞中的转录本计数）。

本项目用的数据是 10x Genomics 平台的输出，标准 10x mtx 格式由三个文件组成：

文件 内容 类比
matrix.mtx.gz 稀疏矩阵：非零表达值 成绩表本体（大部分格子是 0，只存非零）
barcodes.tsv.gz 每个细胞条码（细胞身份证） 学生名单
genes/features.tsv.gz 基因名 科目名

3. 表达型 CNV 推断的原理：为什么”表达”能推断”缺失”

这是一个非常自然的逻辑链：

  1. 缺失了 1 份拷贝的基因，理论上表达量应大约减半（2 份 → 1 份）；
  2. 因此，如果基因组上某一段连续区域的基因在患者细胞里整体表达偏低，就可能暗示这段区域发生了缺失；
  3. infercnvpy（一个公开 Python 包）就是这样做的：把相邻基因的表达信号按基因组坐标窗口平滑，比较患者 vs 对照在每个窗口的平均差异，得到”每个窗口的缺失信号（score）“。score 越负，越像缺失。

但为什么这只是”回退路径”？ 三个原因（图中 infercnv 节点的 tag”回退路径”就是指这个）：

  1. 分辨率极限：1–3 Mb 微缺失只含 25–60 个基因，而窗口平滑要用 25–100 个基因，信号会被稀释；
  2. 剂量补偿 /「mRNA 隐身」：细胞有补偿机制，缺失基因的稳态 mRNA 不一定真的减半。本项目 E8 实验已实测：杂合缺失基因的平均 log2FC ≈ 0.05（≈0），缺失在 mRNA 层面”隐身”了；
  3. 细胞组成混杂：患者和对照的细胞类型比例不同，会在表达信号上造成类似 CNV 的假波动。

所以：缺失区间的权威来源永远是基因型（CNV 芯片 / WGS / MLPA / 临床报告）；表达型推断只是”没有基因型数据时的兜底方案”。

二、数据来源与用处

数据 来源 在本工作流中的用处
GSE283473（GEO 公共数据库） Williams 综合征脑类器官 scRNA-seq，两个样本：GSM8663068_CTRL1（健康对照）、GSM8663071_WS1（患者） 唯一的表达数据。用脑类器官是因为 WBS 有神经发育表型，脑组织最相关
GENCODE v44 GTF（基因注释数据库） 每个蛋白编码基因在 GRCh38 上的坐标（染色体、起止位点） 两处关键用途：① 把表达矩阵的基因按基因组坐标排序（窗口平滑的前提）；② 按已知缺失区间的坐标把基因捞出来

为什么坐标这么重要？ 因为”窗口”和”区间”都是基因组上的物理位置概念。没有 GENCODE 坐标，就不知道”哪些基因在 7q11.23 区间里”。坐标版本必须一致：GSE283473 的 10x 参考是 GRCh38，GENCODE 也必须是 v44（GRCh38），否则区间会错位。

三、五步详解（对照图中泳道 02/03）

第 ① 步 stage-samples：整理样本目录

  • 做什么：把 GEO 下载的原始文件整理成 scanpy 能读的 per-sample 10x 目录。
  • 怎么做：为每个样本建一个目录，用符号链接（symlink）把原始 mtx/barcodes/genes 三件套链进去（不复制，省 100+ MB 空间）；然后把旧的 2 列 genes.tsv 转换成 3 列 features.tsv。
  • 为什么：GEO 提供的 genes.tsv 是旧版 2 列格式（基因 ID + 基因名），而新版 scanpy 只认 3 列 features.tsv（多一个 feature type 列）。不转换会直接报错。这一步很轻量，不依赖 scanpy，纯文件操作。

第 ② 步 prepare-order：基因排序表

  • 做什么：把 GENCODE GTF 解析成一张蛋白编码基因排序表（gene_name、chrom、start、end），按染色体和坐标排好。
  • 怎么做：逐行解析 GTF（gzip 直接读），只保留 protein_coding 类型、只保留 1-22+X+Y 主染色体。
  • 为什么：这张表后面被两个地方复用（图上的两条虚线/灰线”基因排序表”）：
    • infercnv 的”按坐标排序”——窗口平滑要求基因按染色体顺序排列；
    • extract-genes 的”区间→基因”——用坐标判断哪些基因落在缺失区间内。 一次解析、两处消费，所以单独做成一步。

第 ③ 步 infercnv：加载 → QC → 归一化 → 推断（最重的一步）

按顺序四个子操作：

a) 加载 + QC（质控） - min_genes=200：每个细胞至少要测到 200 个基因，否则判为空液滴/测序失败，丢弃； - mito<20%：线粒体基因占比超过 20% 说明是死细胞/破损细胞（细胞质 RNA 泄漏后线粒体 RNA 相对富集），丢弃； - 降采样 8000/样本（seed=0 可重复）：16k 细胞全量跑 infercnvpy 太慢，验证跑随机抽 8000 个细胞。为什么：结果几分钟 vs 几十分钟，且不影响验证结论。 - 原始计数单独存进 layers['counts']——为什么：后面表达 QC 必须用 raw counts（归一化后的数据会丢失测序深度信息）。

b) 归一化 + 按坐标排序 - normalize_total(1e4)：每个细胞的测序深度不同（有的细胞测了 1 万条读段、有的 10 万条），把每个细胞缩放到相同的总计数，消除测序深度差异——否则”深度高”会被误读成”表达高”； - log1p：对数压缩，防止少数超高表达基因主导信号； - 按坐标排序：把基因列重排成染色体 1→22→X→Y、每染色体内按 start 排序，并给每个基因标注 chromosome/start/end。为什么：infercnvpy 的窗口 = “染色体上位置相邻的 100 个基因”，不排序窗口就没有意义。

c) infercnvpy 窗口推断（两档分辨率） - standard（窗口 100 基因 / 步长 10）：全基因组稳定，信号平滑但会稀释 25–60 基因的小缺失； - fine（窗口 25 / 步长 5）：专门针对 1–3 Mb 微缺失，灵敏度高但噪声更大； - 为什么两档都要：standard 看大局、fine 抓小缺失，互为印证。 - 排除 chrX/chrY（重要防坑）：男性只有 1 条 X、女性 2 条，性染色体剂量差异会在 X 染色体上制造巨大假缺失信号，必须从自动发现里排除（已知区间在性染色体上时仍可提取基因，只是不做表达型验证）。

d) 产出窗口信号表 - 每个窗口一行：chr/start/end、score（患者细胞 X_cnv 均值）、ref_score（对照细胞均值，sanity check 应该≈0）。 - 一个硬断言（代码里 window_table() 会校验重建的窗口数与 X_cnv 列数一致）：为什么——infercnvpy 版本变更可能导致窗口布局不匹配，宁可显式报错也不要静默错位。

第 ④ 步 call-segments：robust z 找缺失片段

  • 做什么：从窗口信号表里找出”连续显著偏低”的片段。
  • 怎么做（三步，纯 numpy/pandas，不依赖 scanpy，可单测）：
    1. robust z：z = (score − 全基因组中位数) / (1.4826 × MAD)。为什么不用普通 z（均值/标准差）：普通 z 会被少数极端值（真实缺失信号）拉偏；median/MAD 是稳健统计量，而”单个小缺失几乎不会移动全基因组中位数”（segments.py 注释原文），所以以全基因组为背景找偏差是合理的；
    2. 找 z ≤ −1.5 的连续窗口段，长度 ≥ 3 个窗口才算片段（过滤孤立噪声点）；
    3. 大小过滤 ≤ 10 Mb：超过 10 Mb 的”大缺失”多半不是真的——为什么：着丝粒和低可比对区（重复序列多、测序读段比对不上去）会产生大范围假性低信号，真正的微缺失只有 1–3 Mb。
  • 产出：片段表（segments_standard.csv / segments_fine.csv）。

第 ⑤ 步 extract-genes：区间 → 基因 → QC → 验收

  • 做什么：从”已知临床区间 + 自动发现片段”提取基因清单，并做表达 QC 和验收判定。
  • 怎么做：
    1. 区间 → 基因：用 prepare-order 的排序表，按 GRCh38 坐标把落在区间内的基因捞出来。已知区间 = Williams 7q11.23（chr7: 72.7–74.8 Mb，含 marker 基因 ELN/GTF2I/LIMK1/CLIP2）；自动片段 = 第 ④ 步的产物；
    2. 表达 QC（防 E6 型 pivot）：对每个区间基因统计患者 vs 对照的平均计数、表达细胞比例、log2FC（用 raw counts + 0.5 伪计数）。为什么：如果某个候选基因在这个数据集里几乎不表达（如脑类器官里的血管/上皮基因 ELN、CLDN3），下游 L3 扰动工具根本没法用它——必须先标出来；
    3. 验收判定（AC）：AC-CNV-1 = 自动片段是否覆盖已知区间 ≥50%；AC-CNV-2 = marker 基因是否都在表达数据里检出。
  • 产出：
    • candidates.csv（L1 管线输入，默认只含已知区间的 35 个基因）——为什么：已知区间来自临床确诊，可靠；自动片段只是表达型推断的探索性结果，不可靠，所以默认不混入；
    • candidates_all.csv（2488 基因，已知+自动并集，供探索）；
    • auto_segment_genes.csv（仅自动片段）、validation_known_intervals.csv（AC 判定）、cnv_report.md。

src.ai_scores deeplof 接收预计算 CSV，必需列为 ensembl、gene_symbol、DeepLOF_score，且至少有一行。这里每条评分记录必须具有 [0, 1] 内的有限数值；空值、非数值、NaN/Inf 和越界值会报错，不自动补零或裁剪。此要求针对原始评分转换表；上文合并后证据中“某个基因没有该项证据”的缺失含义不变。

转换以源记录的 Ensembl ID 对照 HGNC 表中的 ensembl_gene_id，只接受唯一对应关系；不再用基因名替代未匹配的 Ensembl ID。若基因名和 Ensembl ID 各自指向不同 HGNC ID，该条记录也不写入评分表。两类排除项的行号、源标识、候选 HGNC ID 和数量都记入审计 JSON，供后续核查；这不是断言被排除的源记录无生物学价值。当前转换结果只含 hgnc_id,DeepLOF_score 两列。

映射后，同一 HGNC ID 的相同分数仍保留一条，并在审计中记录去重数量和规则。如果分数不同，报出冲突数量及前 10 条源记录（数据行号、Ensembl、符号、HGNC ID、分数），停止写出。程序不取均值、最大值或默认第一条，不更改输入文件。

所有输入校验、冲突检测、统计和审计内容准备完成后才写结果。输入错误时 CLI 返回 2，保留已有结果与审计；旧文件存在不代表本次成功。本保护不承诺磁盘故障或进程中断时两个输出文件的事务回滚。
