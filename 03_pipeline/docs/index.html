把候选基因统一到 HGNC 编号，接入公共证据，再生成排名与解释报告。排名用于安排研究优先级，不能单独证明因果或治疗效果。

→
② 合并证据ClinGen / gnomAD / HPA
→
③ 评分与报告排名 CSV + 审计记录

核心筛选不需要 GEO 单细胞数据。CNV 是可选上游；只有已知区间时，也可以直接提取候选。

5.3 为什么尝试 CNV，又没有用于正式候选发现

尝试的目的：探索能否从患者与对照的单细胞表达中推断缺失区间，获得候选基因。

实际结果：真实数据的“自动找回已知缺失区间”检查未通过；标记基因能检测到，并不代表缺失已被识别。另外有 126 个编号尚未匹配当前注释。工程运行检查通过，不能替代这两类科学限制。

现在的选择：筛选从候选列表或已知区间开始。CNV 自动推断暂缓开发，保留代码与探索记录；其中的区间提取和追溯代码仍供主线使用。我们没有证明自动推断失败的具体机制，也不据此否定所有 CNV 方法。

6.2 证据表的必需字段

consensus_v2 的 --ai-scores / --compensation 只用于补充尚未接入的证据。若可选表与已有证据含同名非连接键列，会报出可选表路径和冲突列，退出 2，不覆盖排名、报告或审计。请自行确定来源：保留已有证据时不再传重复表；采用新来源时，先明确移除输入证据中的冲突列，再接入新表。程序不自动覆盖或合并两套分数，也不修改输入文件。

合并前按数据源检查以下字段（列名去首尾空白并转小写后检查）：

  • ClinGen：#Gene Symbol 表头、Haploinsufficiency Score、Triplosensitivity Score 必需；PMID、评估日期等注释可选。
  • gnomAD：基因符号列 gene（或 gene_symbol）、pli、oe_lof_upper 必需；gene_id 等额外信息可选。
  • HPA：Gene name、Tissue、nTPM 必需；组织覆盖不足不属于表结构错误，按下节警告和展示。

缺少必需字段时，CLI 明确报出数据源、文件路径和缺失字段，返回状态码 2，不写证据表或审计文件。已有输出原样保留，不代表本次运行成功。列存在但个别基因的值为空、或基因未匹配到证据，仍按原规则保留缺失值，不补零、不丢弃候选。

审计文件 data_checksums.txt 和 run.json 的 data_checksums 均使用数据文件名作为标识；实际读取目录单独保留在 run.json 的 data_directory 中。文件校验和用于核对内容，目录用于追溯读取位置；统一标识不重写历史审计记录。

6.3 评分配置与错误输出保护

核心 CLI（normalize、merge_evidence、consensus_v2）在写入前检查输出路径：输出不得覆盖本次输入，排名、报告和审计不得指向同一文件，也不得形成文件/目录或父子路径冲突；符号链接与硬链接的同文件冲突同样拒绝，退出码为 2，已有文件保持不变。相同输入可以重复写入原输出位置；不同疾病仍应指定独立目录。此检查不提供并发写入锁或磁盘故障时的事务回滚，失败时不能把保留的旧结果当成本次成功产物。

consensus_v2 的有效评分配置必须使用有限数值：证据权重/序数尺度/低分惩罚、HPA 阈值/权重/上限、调权网格/目标数量、隐性倍率和缺失率阈值均拒绝 NaN、正负无穷大。错误提示包含字段路径；直接调用 run_consensus 也执行相同检查。合法负惩罚、零权重和证据缺失规则不变，不自动替换坏参数或调整评分方法。

即使参数本身有限，数值过大仍可能计算溢出；普通评分、调权、敏感性评分和 Borda 结果均在排名前检查有限性。上述错误使 CLI 以状态码 2 停止，不新建或覆盖排名 CSV、报告及审计文件。已有文件仅代表上次结果，不能据其存在判断本次成功；本保护不等于所有写盘故障均可事务回滚。

可选模块与旧入口的失败处理（2026-09-24）

  • src.compensation：候选表为空或没有任何候选匹配表达矩阵时，明确失败且不写输出；部分匹配仍计算已匹配基因，缺失基因继续警告，不改变相对表达公式或分类。请检查候选符号与表达矩阵 var_names，不要把“无法评估”解释为“没有补偿效应”。
  • src.ai_scores deeplof：转换前检查非空输入及 [0, 1] 内的有限分数；按 Ensembl ID 唯一对应 HGNC，未匹配及与符号不一致的记录排除并审计；同一 HGNC 的不同分数仍明确拒绝，相同分数去重并记录。见 DeepLOF 数据契约与身份核对。正式历史结果不会自动重算或覆盖。
  • 旧 src.consensus（v1）：可以不传 --ai-scores；但一旦显式指定，读取或连接失败就报错停止，不再跳过后生成“成功”的排名。此修复不升级 v1 的科学方法，当前推荐入口仍为 src.consensus_v2。

上述输入错误返回状态码 2，不新建或覆盖结果；DeepLOF 审计、v1 报告也保持原样。成功运行仍沿用各入口原有写出行为。务必检查退出码，已有文件仅代表此前结果；不承诺任意写盘故障的事务回滚。

6.4 分表型证据面板（不改变排名）

首批计划用于 WHS，但研究负责人尚未确定“表型—组织”的对应关系，因此默认 phenotype_panels: []，不自动生成疾病对应关系或空泛的表型结论。确认后，在本次运行的完整配置中替换此字段，例如：

# 仅演示配置格式，不是 WHS 的医学对应关系；使用前替换疾病、表型和组织。
phenotype_panels:
  - id: example_a
    disease: 示例疾病
    phenotype: 待确认的表型名称
    tissues: [cerebral cortex, cerebellum]

id 必须唯一；疾病和表型名称非空；tissues 为非空、无重复的列表，名称须与 HPA Tissue 的原始值完全一致（不能用聚合器官名替代具体组织）。每次使用一个疾病的候选输入和对应配置；配置中的疾病名称只是展示标签，不负责过滤候选或判断疾病归属。合并和评分必须传入同一份配置，并重新运行这两步，不能只用旧证据表生成新面板。

数据流为：HPA 原始组织 nTPM → evidence.parquet 的 hpa_tissue::<组织名>::ntpm 附加列 → 排名 CSV 保留这些列 → v2 Markdown 报告分表型展示。相同 HGNC/组织存在多条记录时沿用原有最大值聚合，不改变原来的器官聚合列。面板列出所有候选（不受报告 Top-N 限制）、原总排名/总分、可用的 ClinGen/gnomAD 证据和各组织 nTPM；不产生表型分数，不重新排序，不筛掉低排名或未解析的候选。

组织缺失时，合并阶段打印警告并在 audit/run.json 的 hpa_coverage 记录器官与面板覆盖。部分组织可用时保留现有数据并列出缺项，整组不可用时标记无法评估，不阻止其他组。评分审计的 results.phenotype_panels 和报告记录本次证据表的组织列覆盖、具表达记录的候选数；报告还列出每个基因的覆盖数。无组织列可能是源数据缺失，也可能是未按该配置重新合并；不能解释为组织不表达。源中无可映射的有效 nTPM 同样视为不可用；逐基因缺失显示“无数据”，实测 0 保留为 0。

默认关闭面板时，原有证据和排名列不变；启用时增加注释列和报告内容，不修改权重、总分、总排名、Borda 或敏感性分析。表达仅作为组织背景，不证明某基因导致某表型。分表型独立排名另记 CR-049，按负责人决定延期。

6.5 候选字段与未解析编号

候选输入必须包含 gene_symbol。标准化输出包含 hgnc_id、input_symbol、status，并按行保留输入中已有的 source、deletion_id、chrom、start、end；这五列会继续传递到证据表和最终排名 CSV，不参与评分。没有这些可选字段的输入仍输出原来的三列；其他自定义列不在本次保留范围内。

当前标准化只匹配 HGNC 正式符号及其历史/别名，不自动转换 Ensembl ID。未匹配行保留原编号并标记 status=unresolved、hgnc_id 为空；未解析比例超过 10% 时，CLI 写出结果后返回非零状态，阈值保持不变。2026-09-22 复核中，WBS 的 ENSG00000289346 仍未解析（1/35，约 2.9%），WHS 无未解析项；该编号尚未映射到 HGNC，不代表它是无效编号，后续需单独核实。

空文件、仅空白内容或只有表头而没有候选行的输入会提示 candidate input is empty; check input or upstream filtering results，CLI 返回状态码 2，在读取 HGNC 表和创建输出目录前停止；已有输出文件保持不变，不能将它当作本次成功结果。直接调用 resolve 传入空表会抛出明确的 ValueError。有候选行但符号为空仍按 unresolved 处理，不混同于零行输入。

HGNC 历史/别名字段会先清理首尾空白及成对外层双引号，再按 |、;、, 拆分；正式符号优先，关联多个 HGNC 的歧义别名不自动匹配。别名识别改善后，重新生成全基因 AI 表可能改变覆盖和分数；2026-09-22 的历史变化见项目日志条目 #24，CR-046 的后续身份映射修复及影响见条目 #49。已有评分文件不会自动更新。

6.6 模式与解释

src.consensus_v2 支持 auto、validate、rank、full、exploratory。rank 用于有争议候选排序；validate 面向预先确定的基因；full 加入补偿状态集成；exploratory 面向未知区间，不给实验建议。配置权重在 config/。当前 WBS 正对照清单是 4 个，不是旧文档所写的 6 个；旧 WHS 输出使用过不同配置，不能当作当前配置的逐值基准。

AI 预评分文件 outputs/ai_scores.csv 是可选输入，不能替代 ClinGen、gnomAD、HPA 数据。CNV 单细胞工作流是可选上游功能，见 docs/cnv_workflow.md；其 Python 依赖已包含在统一的 requirements.txt 中，但仍需下载六个原始 GEO 文件，再由 stage-samples 重建样本布局。不要使用历史留下的、指向项目外部的样本符号链接。

实验归档与历史输出索引见 outputs/README.md。历史记录只说明当时运行条件，不保证与现行配置一致。
