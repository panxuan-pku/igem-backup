# CNV 工作流详解：从 scRNA-seq 到候选基因

> 配套图：`igem_cnv.workflow.html`（Archify 交互式流程图，浏览器打开）
> 源文件：`igem_cnv.workflow.json`
> 本文对照图中 4 条泳道、11 个节点逐一讲解：先讲基础概念，再讲每一步"做什么 → 怎么做 → 为什么这么做"。

## 一、先搞懂三个基础概念

### 1. CNV 与微缺失：什么是"拷贝数变异"

正常人体细胞每条常染色体有 **2 份拷贝**（一份来自父亲、一份来自母亲）。**CNV（Copy Number Variation，拷贝数变异）**就是基因组上某一段 DNA 的拷贝数发生了变化：

- **缺失（deletion）**：2 份 → 1 份（**杂合缺失**）或 2 份 → 0 份（纯合缺失）
- **重复（duplication）**：2 份 → 3 份或更多

本项目关注的是 **微缺失（microdeletion）**：长度 1–3 Mb（百万碱基对）的小段缺失，典型例子就是 **Williams 综合征（WBS）**——7 号染色体 7q11.23 区域约 1.55 Mb 的杂合缺失，包含约 25–35 个蛋白编码基因。

**为什么微缺失会致病？** 关键机制叫**单倍剂量不足（haploinsufficiency）**：某些基因必须要有 2 份拷贝才能产生足够的蛋白；只剩 1 份时蛋白量减半，功能就不够了。所以 iGEM 项目的核心问题是：**缺失区间里有 30 多个基因，到底哪一个（或哪几个）是导致疾病的主效基因？** CNV 工作流的任务就是从这个区间里产出"候选基因清单"。

### 2. scRNA-seq：单细胞表达数据是什么样

**scRNA-seq（单细胞 RNA 测序）**测的是**每个细胞里每个基因的表达量**——即"哪个细胞表达了哪个基因、表达了多少"。

- 普通 bulk RNA-seq：把一堆细胞磨碎混在一起测，得到平均值；
- scRNA-seq：每个细胞单独测，得到一张 **细胞 × 基因的矩阵**（每行一个细胞，每列一个基因，数值 = 该基因在该细胞中的转录本计数）。

本项目用的数据是 **10x Genomics** 平台的输出，标准 **10x mtx 格式**由三个文件组成：

| 文件 | 内容 | 类比 |
|---|---|---|
| `matrix.mtx.gz` | 稀疏矩阵：非零表达值 | 成绩表本体（大部分格子是 0，只存非零） |
| `barcodes.tsv.gz` | 每个细胞条码（细胞身份证） | 学生名单 |
| `genes/features.tsv.gz` | 基因名 | 科目名 |

### 3. 表达型 CNV 推断的原理：为什么"表达"能推断"缺失"

这是一个非常自然的逻辑链：

1. 缺失了 1 份拷贝的基因，理论上表达量应**大约减半**（2 份 → 1 份）；
2. 因此，如果基因组上**某一段连续区域的基因**在患者细胞里**整体表达偏低**，就可能暗示这段区域发生了缺失；
3. **infercnvpy**（一个公开 Python 包）就是这样做的：把相邻基因的表达信号按基因组坐标**窗口平滑**，比较患者 vs 对照在每个窗口的平均差异，得到"每个窗口的缺失信号（score）"。score 越负，越像缺失。

**但为什么这只是"回退路径"？** 三个原因（图中 infercnv 节点的 tag"回退路径"就是指这个）：

1. **分辨率极限**：1–3 Mb 微缺失只含 25–60 个基因，而窗口平滑要用 25–100 个基因，信号会被稀释；
2. **剂量补偿 /「mRNA 隐身」**：细胞有补偿机制，缺失基因的稳态 mRNA 不一定真的减半。本项目 E8 实验已实测：杂合缺失基因的平均 log2FC ≈ 0.05（≈0），缺失在 mRNA 层面"隐身"了；
3. **细胞组成混杂**：患者和对照的细胞类型比例不同，会在表达信号上造成类似 CNV 的假波动。

所以：**缺失区间的权威来源永远是基因型**（CNV 芯片 / WGS / MLPA / 临床报告）；表达型推断只是"没有基因型数据时的兜底方案"。

## 二、数据来源与用处

| 数据 | 来源 | 在本工作流中的用处 |
|---|---|---|
| **GSE283473**（GEO 公共数据库） | Williams 综合征**脑类器官** scRNA-seq，两个样本：`GSM8663068_CTRL1`（健康对照）、`GSM8663071_WS1`（患者） | 唯一的表达数据。用脑类器官是因为 WBS 有神经发育表型，脑组织最相关 |
| **GENCODE v44 GTF**（基因注释数据库） | 每个蛋白编码基因在 GRCh38 上的坐标（染色体、起止位点） | 两处关键用途：① 把表达矩阵的基因**按基因组坐标排序**（窗口平滑的前提）；② 按**已知缺失区间的坐标**把基因捞出来 |

**为什么坐标这么重要？** 因为"窗口"和"区间"都是**基因组上的物理位置**概念。没有 GENCODE 坐标，就不知道"哪些基因在 7q11.23 区间里"。**坐标版本必须一致**：GSE283473 的 10x 参考是 GRCh38，GENCODE 也必须是 v44（GRCh38），否则区间会错位。

## 三、五步详解（对照图中泳道 02/03）

### 第 ① 步 stage-samples：整理样本目录

- **做什么**：把 GEO 下载的原始文件整理成 scanpy 能读的 per-sample 10x 目录。
- **怎么做**：为每个样本建一个目录，用**符号链接**（symlink）把原始 mtx/barcodes/genes 三件套链进去（不复制，省 100+ MB 空间）；然后把旧的 **2 列 genes.tsv 转换成 3 列 features.tsv**。
- **为什么**：GEO 提供的 genes.tsv 是旧版 2 列格式（基因 ID + 基因名），而新版 scanpy 只认 3 列 features.tsv（多一个 feature type 列）。不转换会直接报错。这一步很轻量，**不依赖 scanpy**，纯文件操作。

### 第 ② 步 prepare-order：基因排序表

- **做什么**：把 GENCODE GTF 解析成一张**蛋白编码基因排序表**（gene_name、chrom、start、end），按染色体和坐标排好。
- **怎么做**：逐行解析 GTF（gzip 直接读），只保留 `protein_coding` 类型、只保留 1-22+X+Y 主染色体。
- **为什么**：这张表后面被**两个地方**复用（图上的两条虚线/灰线"基因排序表"）：
  - infercnv 的"按坐标排序"——窗口平滑要求基因按染色体顺序排列；
  - extract-genes 的"区间→基因"——用坐标判断哪些基因落在缺失区间内。
  一次解析、两处消费，所以单独做成一步。

### 第 ③ 步 infercnv：加载 → QC → 归一化 → 推断（最重的一步）

按顺序四个子操作：

**a) 加载 + QC（质控）**
- `min_genes=200`：每个细胞至少要测到 200 个基因，否则判为空液滴/测序失败，丢弃；
- `mito<20%`：线粒体基因占比超过 20% 说明是死细胞/破损细胞（细胞质 RNA 泄漏后线粒体 RNA 相对富集），丢弃；
- **降采样 8000/样本**（seed=0 可重复）：16k 细胞全量跑 infercnvpy 太慢，验证跑随机抽 8000 个细胞。**为什么**：结果几分钟 vs 几十分钟，且不影响验证结论。
- 原始计数单独存进 `layers['counts']`——**为什么**：后面表达 QC 必须用 raw counts（归一化后的数据会丢失测序深度信息）。

**b) 归一化 + 按坐标排序**
- `normalize_total(1e4)`：每个细胞的测序深度不同（有的细胞测了 1 万条读段、有的 10 万条），把每个细胞缩放到相同的总计数，**消除测序深度差异**——否则"深度高"会被误读成"表达高"；
- `log1p`：对数压缩，防止少数超高表达基因主导信号；
- **按坐标排序**：把基因列重排成染色体 1→22→X→Y、每染色体内按 start 排序，并给每个基因标注 chromosome/start/end。**为什么**：infercnvpy 的窗口 = "染色体上位置相邻的 100 个基因"，不排序窗口就没有意义。

**c) infercnvpy 窗口推断（两档分辨率）**
- **standard（窗口 100 基因 / 步长 10）**：全基因组稳定，信号平滑但**会稀释 25–60 基因的小缺失**；
- **fine（窗口 25 / 步长 5）**：专门针对 1–3 Mb 微缺失，灵敏度高但**噪声更大**；
- **为什么两档都要**：standard 看大局、fine 抓小缺失，互为印证。
- **排除 chrX/chrY**（重要防坑）：男性只有 1 条 X、女性 2 条，性染色体剂量差异会在 X 染色体上制造巨大假缺失信号，必须从自动发现里排除（已知区间在性染色体上时仍可提取基因，只是不做表达型验证）。

**d) 产出窗口信号表**
- 每个窗口一行：chr/start/end、`score`（患者细胞 X_cnv 均值）、`ref_score`（对照细胞均值，sanity check 应该≈0）。
- 一个**硬断言**（代码里 `window_table()` 会校验重建的窗口数与 X_cnv 列数一致）：**为什么**——infercnvpy 版本变更可能导致窗口布局不匹配，宁可显式报错也不要静默错位。

### 第 ④ 步 call-segments：robust z 找缺失片段

- **做什么**：从窗口信号表里找出"连续显著偏低"的片段。
- **怎么做**（三步，纯 numpy/pandas，不依赖 scanpy，可单测）：
  1. **robust z**：z = (score − 全基因组中位数) / (1.4826 × MAD)。**为什么不用普通 z**（均值/标准差）：普通 z 会被少数极端值（真实缺失信号）拉偏；median/MAD 是稳健统计量，而"单个小缺失几乎不会移动全基因组中位数"（segments.py 注释原文），所以以全基因组为背景找偏差是合理的；
  2. 找 **z ≤ −1.5 的连续窗口段**，长度 ≥ 3 个窗口才算片段（过滤孤立噪声点）；
  3. **大小过滤 ≤ 10 Mb**：超过 10 Mb 的"大缺失"多半不是真的——**为什么**：着丝粒和低可比对区（重复序列多、测序读段比对不上去）会产生大范围假性低信号，真正的微缺失只有 1–3 Mb。
- **产出**：片段表（segments_standard.csv / segments_fine.csv）。

### 第 ⑤ 步 extract-genes：区间 → 基因 → QC → 验收

- **做什么**：从"已知临床区间 + 自动发现片段"提取基因清单，并做表达 QC 和验收判定。
- **怎么做**：
  1. **区间 → 基因**：用 prepare-order 的排序表，按 GRCh38 坐标把落在区间内的基因捞出来。已知区间 = Williams 7q11.23（chr7: 72.7–74.8 Mb，含 marker 基因 ELN/GTF2I/LIMK1/CLIP2）；自动片段 = 第 ④ 步的产物；
  2. **表达 QC**（防 E6 型 pivot）：对每个区间基因统计患者 vs 对照的平均计数、表达细胞比例、log2FC（用 raw counts + 0.5 伪计数）。**为什么**：如果某个候选基因在这个数据集里几乎不表达（如脑类器官里的血管/上皮基因 ELN、CLDN3），下游 L3 扰动工具根本没法用它——必须先标出来；
  3. **验收判定（AC）**：AC-CNV-1 = 自动片段是否覆盖已知区间 ≥50%；AC-CNV-2 = marker 基因是否都在表达数据里检出。
- **产出**：
  - `candidates.csv`（**L1 管线输入，默认只含已知区间的 35 个基因**）——**为什么**：已知区间来自临床确诊，可靠；自动片段只是表达型推断的探索性结果，不可靠，所以默认不混入；
  - `candidates_all.csv`（2488 基因，已知+自动并集，供探索）；
  - `auto_segment_genes.csv`（仅自动片段）、`validation_known_intervals.csv`（AC 判定）、`cnv_report.md`。

## 四、验收结果怎么读（GSE283473 真实数据）

| 门槛 | 结果 | 怎么理解 |
|---|---|---|
| **AC-CNV-2**：marker 基因检出 | ✅ **PASS** | ELN/GTF2I/LIMK1/CLIP2 都在表达数据里。首轮还 FAIL 过：配置把区间终点写成 74.4 Mb，漏掉了位于 74.65–74.76 Mb 的 GTF2I——**验收门槛真的能抓 bug** |
| **AC-CNV-1**：自动发现覆盖已知区间 | ❌ **FAIL（预期内负结果）** | 1.55 Mb 杂合缺失没被表达型推断恢复。原因正是第一节讲的：分辨率极限 + mRNA 隐身。**这不否定缺失存在，也不影响 candidates.csv**（它只依赖已知区间坐标） |
| 区间基因平均 log2FC | ≈ 0.05 | 与 E8「mRNA 隐身」一致：缺失基因的稳态 mRNA 被剂量补偿吸收。这正是表达型推断注定是回退路径的机制原因 |
| 大小过滤 | standard 19/27、fine 7/46 片段被过滤 | 大量 >10 Mb 伪影被正确剔除 |

**一句话总结这条管线**：表达型推断（infercnv + call-segments）负责"在没有基因型时尽力猜测缺失区域"，但**交付给 L1 管线的候选基因永远来自权威的已知临床区间**；表达信号只用来做 QC 和验收。
