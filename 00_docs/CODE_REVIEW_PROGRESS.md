### 历史实验档案专项标准（适用于 R09）

这两个目录的目标不是证明脚本适合长期维护，而是让评委能够理解并核查项目迭代。因此，R09 按以下优先级审查：

1. **叙事完整性**：每个疾病目录说明当时的问题、候选基因、方法选择、预期、实际结果、局限，以及该结果如何促成后续路线变化。
2. **结论真实性**：脚本输出、保存结果和复盘报告相互一致；探索性相关、归因或模拟结果不得表述为已验证的因果结论。
3. **最低可复现性**：记录数据来源、样本、关键参数、随机种子、依赖和执行顺序；缺少原始数据时给出获取与目录布局说明。
4. **方法学可信度**：重点检查样本独立性、数据泄漏、索引/基因对齐、归一化、统计检验和比较口径。会改变科学结论的问题必须修复或醒目标注。
5. **GitHub 可读性与安全**：移除个人绝对路径、固定本机代理、密钥和隐私数据；明确哪些大文件不入库。第三方数据和模型注明来源与许可。
6. **历史真实性**：不为美化代码而重构算法或重写流程。必要修复应记录变更原因；原始结论若被推翻，应保留并标注，而不是删除。

R09 的最低交付物：

- [ ] 两个目录各有 README，并在开头标记“历史探索/非当前推荐流程”。
- [ ] README 包含“问题 → 方法 → 结果 → 局限 → 对下一阶段的影响”的短链路。
- [ ] 关键脚本与输出文件建立对应关系，说明哪些结果可重算、哪些仅作历史留档。
- [ ] 数据来源、样本设计、关键参数、随机性和运行环境足以供评委核查。
- [ ] 修复或记录所有可能改变科学结论的问题。
- [ ] 清除本机代理、个人路径、凭据、隐私数据和不可发布的大文件。
- [ ] 至少完成语法/导入检查；条件允许时执行最小复现，不强求把历史脚本建设为完整测试套件。
- [ ] 与当前主流程建立链接，明确早期方法为何被保留、又为何不再作为最终方案。
