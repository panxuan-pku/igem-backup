SIGnature 与 VirtualCellTool 接入

VCT 源码在 05_virtual_cell/；第三方源码和全部运行数据由使用者另行准备。

1. 两者各做什么

单细胞表达 → SIGnature / SCimilarity 编码和归因 → VCT 展示与实验性探索。

组件 归属与作用 本地位置
SIGnature Genentech 的第三方工具；调用 SCimilarity 等模型，提供编码与归因接口 默认 05_tools/SIGnature/，整个 05_tools/ 不入库
VirtualCellTool 本项目的网页、数据准备和分析整合代码；CIPHER、GEARS 等各有不同用途 05_virtual_cell/，源码和测试保留
数据及模型 原始单细胞矩阵、标签、编码、缓存和模型检查点 本地下载或生成，均不入库

VCT 与核心候选排名管线目前独立，尚未自动串联。编码器位移不是细胞类型转化或治疗效果预测；CIPHER 是线性近似，GEARS 的训练背景也不能直接等同微缺失疾病。外部工作归属见 ATTRIBUTIONS。

2. 获取第三方源码和环境

先安装 Python 3.11，在仓库根目录执行。安装会清除并重建 .venv/pipeline 和 .venv/vct；依赖安装需要网络。

bash scripts/setup_envs.sh
mkdir -p 05_tools
git clone https://github.com/Genentech/SIGnature.git 05_tools/SIGnature

若目录已经存在，不要重复克隆或覆盖。VCT 直接从该 checkout 的 src/ 导入 SIGnature，项目依赖由 requirements-web.txt 安装；无需再向主环境安装一套 SIGnature。独立使用第三方包时，按SIGnature 官方安装说明操作。

可用 SIGNATURE_DIR=/绝对路径/SIGnature 指定其他 checkout，运行准备脚本、测试及服务时保持一致。上游 API 正在演进，当前仓库尚未锁定一个已重新验证的上游 commit；获取后记录 git -C 05_tools/SIGnature rev-parse HEAD 并运行第 5 节兼容性测试。不能把“最新下载成功”当兼容性通过。

3. 下载 SCimilarity 模型

从官方安装页指向的 Zenodo 17903196下载 model_files.tar.gz。该记录含 SCimilarity 权重，文件 MD5 为 ec04ae13a9ecd1ebad7e78b0ea6ae39e。下载后核对校验值；在全新模型目录中解压，使最终路径为：

05_tools/SIGnature/model_files/model_files/scimilarity/
├── encoder.ckpt
├── gene_order.tsv
└── 其余随模型提供的配置文件（完整保留）

例如，压缩包放在 /path/to/model_files.tar.gz 时，在根目录运行：

mkdir -p 05_tools/SIGnature/model_files
tar -xzf /path/to/model_files.tar.gz -C 05_tools/SIGnature/model_files

若使用 SIGNATURE_DIR，在对应目录下保持相同结构。模型目录含两层 model_files 是本项目目前的路径约定。只放权重、不放基因顺序及配置，无法正确运行。

4. 准备自己的演示数据

数据集 来源与生成脚本 仍需注意
PBMC 测试集 src/prepare_data.py 调用 Scanpy PBMC3k；必须自行提供认可的细胞注释 CSV 注释列 cell,cell_type，ID 唯一且完整匹配；cluster 可选。没有可信标签时不能猜测或沿用旧标签
Williams / WS GSE283473 → Williams 预处理 → processed.h5ad → src/prepare_ws_web.py 可用 VCT_WS_H5AD 指定输入；脚本会写 data/ws_*，需先核对分组与预处理，避免覆盖自己的已有结果
MS 少突胶质细胞 历史归属表登记为 CELLxGENE collection 16c1e722；src/compute_ms_attribution.py 和 src/prepare_ms_web.py 缺少完整 collection/dataset ID 和可核验的下载链接，尚不能据此唯一下载历史文件；应先补齐来源。所需输入名为 data/ms_oligodendrocytes.h5ad
GEARS（可选） GEARS 源码、Norman 数据、模型仓库 norman.zip 解压至 gears_data/norman/；检查点与配置放 gears_ckpt/。只在使用 GEARS 时准备

PBMC 的准备命令（在 VCT 目录内）：

cd 05_virtual_cell
../.venv/vct/bin/python src/prepare_data.py \
  --metadata /path/to/approved_pbmc_labels.csv --output outputs/pbmc_run_001

该命令生成新目录，不自动替换网页 data/。核对同一次生成的 expr_aligned.npz、embeddings.npy、meta.csv、umap.npy、gene_order.txt 后整套部署到 data/，不能混用不同运行的矩阵与标签。MS 归因同样生成独立输出目录；必须核对后整套部署，准备脚本不会自动完成全部网页发布步骤。

文件指纹清单列出历史演示所用文件，可辅助核对，但不是可下载的数据包。新克隆默认没有 PBMC/MS/WS 数据；没有准备的页面功能会缺数据，不能宣称三个数据集已经可用。

5. 检查并启动

先在 VCT 目录做离线回归，要求 SIGnature checkout 和 VCT 依赖可导入；历史实数据回归在缺少本地归档时明确跳过：

../.venv/vct/bin/python -m unittest discover -s tests -v
../.venv/vct/bin/python web/app.py

浏览器访问 http://127.0.0.1:8377/。macOS 双击 启动VirtualCellTool.command 使用同一环境。服务启动不代表所有数据集已准备好。

三个数据集都准备好后，可在另一个终端执行 ../.venv/vct/bin/python tests_api.py --skip-gears；GEARS 完整数据就绪后再去掉该选项。历史 API 测试含特定细胞数，主动更换数据时需核对预期；测试通过仍不是科学有效性证明。更详细的端口、停止、浏览器测试和方法边界见 VCT README。
