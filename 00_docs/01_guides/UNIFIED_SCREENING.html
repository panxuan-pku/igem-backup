统一筛选 · 使用指南

给出区间或基因列表，获得一份排名

两种输入，一个流程。第一次先运行小规模基因列表示例。

1 安装2 下载3 运行4 阅读结果5 复现

1. 安装一次环境

需要 Python 3.11、Git 及可访问公开数据库的网络。以下命令从仓库根目录执行（macOS / Linux）。

git clone https://github.com/panxuan-pku/igem-backup.git
cd igem-backup
bash scripts/setup_envs.sh --pipeline-only

已经安装环境时跳过本步；安装脚本会重建 .venv/pipeline。

2. 下载并固定一套参考

.venv/pipeline/bin/python scripts/run_screening.py prepare \
  --references 03_pipeline/data/screening_refs

自动下载 GENCODE v44 完整注释、HGNC、ClinGen、gnomAD v4.1.1 和 HPA v24，并生成版本与校验值清单。下载量比旧快速示例大，主要来自新版 gnomAD 文件；请留出数 GB 磁盘空间，耐心等待。

失败后可再次执行同一命令，已完成且校验一致的文件会复用。不要手动改动参考目录；更新数据时使用新的目录名。

3. 选择一种输入

3.1 第一次运行：四基因演示

.venv/pipeline/bin/python scripts/run_screening.py run \
  --references 03_pipeline/data/screening_refs \
  --genes NSD2 LETM1 NELFA FGFR3 \
  --input-source "four-gene engineering demonstration"

这四个基因用于演示流程，不是完整的 WHS 缺失基因集合，也不是正式 Wiki 筛选结果。默认 OT 疾病编号为 WHS 的 MONDO_0008684。

3.2 使用你自己的缺失基因列表

创建一个纯文本文件，每行一个基因、不带表头。支持 HGNC ID、Ensembl gene ID 或可唯一解析的符号；同一基因只写一次。

.venv/pipeline/bin/python scripts/run_screening.py run \
  --references 03_pipeline/data/screening_refs \
  --gene-list /完整路径/genes.txt \
  --input-source "该列表的文献、样本或数据来源"

3.3 使用具体缺失区间

用实际坐标替换下方占位符，去掉千位逗号。仅接受 GRCh38、1-based inclusive。程序保留所有重叠的蛋白编码基因，并标记部分重叠；不自动将 GRCh37 或 BED 坐标转换。

.venv/pipeline/bin/python scripts/run_screening.py run \
  --references 03_pipeline/data/screening_refs \
  --interval 'chr4:起点-终点' \
  --input-source "区间的文献、样本或数据来源"

WHS 没有在软件中硬编码的通用缺失区间。若研究其他疾病，额外提供 --disease-id 疾病编号；它改变 OT 注释对象，不改变核心权重。

4. 打开结果，先看三件事

终端会打印 report.html 的完整位置，直接用浏览器打开。默认每次生成新的 03_pipeline/outputs_repro/screening_时间/，不覆盖旧结果。

要看什么怎么理解
排名与证据rank 越小越靠前；分数是本次集合内的相对排序，不是概率。完整 CSV 保留单项贡献和原始证据。
注释是否齐全OT 的 no_record、query_failed 和真实 0 分不同；IMPC 未提供时标记 not_supplied。所有这些注释不改变主排名。
设计状态selected 表示通过 3′UTR ≥30 bp 且在模块预算内。没有入选时查看 selection_reason：长度不足、转录本未确定或预算不足。

ClinGen 隐性疾病关联、小鼠 viable 不自动排除。部分区间覆盖、缺少证据等限制见注释。具备长度和预算条件不代表完整构建、包装或治疗效果已经验证。

可选参数与文件

--module-budget 4400 --module-size 300 修改预算假设。--phenotype-id 编号 可重复使用，将预先选定的表型另列注释，默认空。--output 新目录 自定输出位置，必须尚不存在。

--impc-evidence /路径/impc.tsv 导入已核验的人鼠同源证据。必需列为 gene_id、mouse_gene_id、impc_viability、source、release、mapping_source，其中 gene_id 为候选的人类 Ensembl gene ID，一行一个基因；存活状态限 viable / subviable / lethal / unknown。不以人类符号首字母大小写猜测小鼠身份。

5. 重复运行与问题处理

重复使用同一参考目录可以保持文件版本；添加 --ot-snapshot 旧结果目录/ot_snapshot.json 可重放该次 OT 注释，不再访问 API。必须覆盖本次候选，且疾病、表型列表及 release 相符。

OT 实时版本与配置不符时，报告标记注释失败，核心排名仍可完成，但不能当作 OT 注释齐全。不要把版本错误改成 0 分；应复用匹配快照，或明确升级配置后重新核验。

遇到身份歧义、证据格式错误或参考校验不一致，程序会停止并显示原因。结果目录如已创建，manifest.json 记录失败状态。超过半数候选没有任何可计分核心证据时同样停止。

科学数据和运行结果不进入 Git。正式发布前另行归档需要共享的输入与快照；历史数据无法仅凭哈希恢复。

6. 理解方法与历史入口
