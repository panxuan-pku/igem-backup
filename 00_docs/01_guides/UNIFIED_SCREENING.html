1. Setup and complete examples

The root README is the current step-by-step guide for macOS, Linux and Windows. Section 2 runs the ClinGen WHS reference interval; section 3 provides the complete gene-list route. Both use the virtual-screening Conda environment.

conda env create --file environment.yml
conda activate virtual-screening
python scripts/test_pipeline.py --suite environment

2. Prepare versioned references

python scripts/run_screening.py prepare

Downloads GENCODE, HGNC, ClinGen, gnomAD and HPA to 03_pipeline/data/screening_refs/, with versions and checksums in references.json. The first download is approximately 617 MiB; verified local files are reused. The ClinGen region table for WHS input is a separate file.

3. Prepare inputs, then run

Use scripts/prepare_screening_input.py to convert TXT/CSV/TSV gene lists or BED/ClinGen/CSV/TSV interval tables. Follow the README conversion commands before running:

python scripts/run_screening.py run --input-file 03_pipeline/input/whs_interval_input.json --output 03_pipeline/outputs_repro/whs_interval_01

python scripts/run_screening.py run --input-file 03_pipeline/input/gene_list_input.json --output 03_pipeline/outputs_repro/gene_list_01

Run the command matching your prepared input. Intervals use GRCh38, 1-based inclusive coordinates; the BED converter adjusts coordinate conventions but does not perform genome-build conversion. Interval input retrieves overlapping protein-coding genes and flags partial overlaps. Gene-list input covers only submitted candidates.

The WHS example uses ClinGen ISCA-37429, not a patient-specific deletion or the historical 19-gene set. The default OT disease is MONDO_0008684; change --disease-id for another disease.

4. Read results

Open interval_report.html or gene_list_report.html. Each run writes seven files prefixed with its input type: report, summary, ranked evidence, candidates, manifest, configuration and OT snapshot. CSV files use UTF-8 with BOM.

FieldInterpretation
rank / consensus_scoreRelative research priority within the candidate set, not a probability. ClinGen and gnomAD contribute to the score.
ot_statusNo record, failed query and an actual zero score are distinct. OT, HPA and IMPC annotations do not change ranking.
selected / selection_reasonProject 3′UTR minimum of 30 bp plus the fixed module budget. Candidates failing these conditions remain in the ranking.

ClinGen recessive association and IMPC mouse viability do not automatically exclude candidates. Design checks do not validate full constructs, packaging, specificity or therapeutic effects.

Optional arguments

--module-budget 4400 --module-size 300 changes budget assumptions. Repeat --phenotype-id ID to add prespecified phenotype annotations. --output NEW_DIRECTORY selects a directory that does not yet exist. Use the same --references DIRECTORY for preparation and screening.

--impc-evidence FILE.tsv accepts verified human-to-mouse evidence with columns gene_id, mouse_gene_id, impc_viability, source, release, mapping_source. Use one row per human Ensembl gene ID. Viability states are viable / subviable / lethal / unknown; mouse identity is not inferred by changing symbol capitalization.

5. Reproduction and troubleshooting

Retain the same input, references and configuration. Add --ot-snapshot previous_run/interval_ot_snapshot.json (or gene_list_ot_snapshot.json) to replay annotations without API requests. The snapshot must match the candidates, disease, phenotypes and release.

OT failures produce [WARN] Ranking generated and annotation gaps; do not interpret them as no association. Identity ambiguity, reference checksum mismatch or invalid evidence stops screening with [FAIL]. If a run directory has been created, its typed manifest records the failure. More than half of candidates lacking usable core evidence also stops screening.

Each default output directory starts with interval_ or gene_list_ followed by a timestamp. Existing results are never renamed by the new convention.

6. Current and historical entry points

Use run_screening.py with config/screening.yaml for unified screening. The Williams run_quickstart.py and pipeline.yaml remain historical compatibility routes with their own output contracts. See the README repository map to distinguish current tools from research archives.
