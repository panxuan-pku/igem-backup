把候选基因变成可追溯的优先级

主线服务于人类微缺失研究：整理候选，连接证据，生成排名与报告。不同疾病分别运行，共用同一套代码。

1. 核心流程

已有候选列表可以直接进入；只有已知缺失区间时，先根据匹配版本的基因注释提取候选。

步骤 1候选基因
列表或已知区间
→
步骤 2整理名称
保留来源和异常
→
步骤 3连接证据
身份、约束、表达等
→
步骤 4排名与报告
附依据和运行审计

2. 每次运行要说清什么

研究与输入

疾病/研究、候选来源、输入和输出位置、所用配置。

控制基因

控制基因必须明确指定；暂未确定就填 []，报告会注明“未评估”。

3. 系统怎样处理冲突

重复来源

同研究跨区间重复提取的同一基因只排名一次，保留所有来源。

身份与位置不确定

无法确定身份或位置时明确报告；原始计数按唯一编号保留每行。

4. 已有工程验收，科学解释仍有边界

2026-09-25 的当前环境和同一电脑上新建的独立环境各通过 445 项测试（零跳过），核心 WBS/WHS 结果与基线一致。它支持已测流程的可靠性；候选排名仍需后续生物学证据解释。

这是既有验收记录。本轮仅调整文档，没有重跑这些测试。

5. 编号修复：完成了什么，限制在哪里

同名基因导致的程序阻塞已经解除。原始符号和每行计数按唯一编号保留；工程验收已完成。CNV 自动识别已知缺失仍未成功，后续 CNV 工作继续暂停。

5.1 修复了什么

真实运行遇到两个都叫 NOX5 的不同编号。现在用编号匹配注释和位置，原来的名字照常保留；每行计数跟着自己的编号走，不相加、不改名、不加后缀。找不到注释或位置有歧义时明确报告。

区间表达检查也按编号对应：区间外的同名基因有表达，不能当成区间内这个编号有表达。

5.2 为什么有两类候选表

候选表本次六样本结果后续用途
探索表2,350 个编号；不同编号即使同名也分行保留保存自动发现的线索，未自动送入正式排名
正式候选表已知缺失区间中的 35 个候选进入评分与排名，继续检查符号唯一性

把身份有冲突的探索候选送进正式入口时，程序仍会报错，要求先解决身份问题。

5.3 怎样验证修复有效

  1. 真实数据：Williams 研究的 3 个患者样本和 3 个对照样本，按原筛选规则最终分析 48,000 个细胞。保留基因行的计数、原符号、细胞身份和患者/对照标签均逐样本核对一致。
  2. 重复与隔离：六样本重复运行结果一致；另外两个样本在单独目录运行，没有改变六样本输出。
  3. 核心排名：Williams（WBS）与 Wolf–Hirschhorn（WHS）的核心排名和报告与修复前基线一致。
  4. 自动检查：两个环境各 445 项通过、零跳过。独立环境是在同一电脑中新建的环境，并非新机器验收，也不代表候选获得生物学验证。

当次修复没有修改原始数据、正式评分表、评分权重或原有筛选阈值，也没有提交或推送 Git。本页整理上述历史结果，没有重跑验收。
