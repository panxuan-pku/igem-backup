## 2026-09-16 追加复核：暂缓执行删除

本清单下文的体积、重复性判断和“可删依据”是**历史迁移记录，不是当前删除授权**。本轮已在不含旧 `.venv`、嵌套 `.git` 和越界样本链接的 `08_gitlab_export/` 中新建环境：管线测试 22 通过/1 跳过，WBS/WHS 排名与报告均生成；VirtualCellTool 三数据集、CIPHER、反事实和 GEARS 均已产生结果。`scripts/check_release.py` 检查 45 个关键文件通过。

但**尚未完成实际 GitLab 上传后的重新克隆验收**：此机器没有 `git lfs`，因此无法验证大文件是否真正作为 LFS 对象上传、GitLab 配额与新用户下载。旧项目副本和下面第 1–5 项一律先保留，不按旧顺序清理。Hermes 数据库备份（第 4 项）与 iGEM 可复现性无关，必须另行核实主库及所需历史记录，不能据本次工具测试删除。

清理前的最低门槛：先安装 Git LFS，从 `08_gitlab_export/` 建库并确认 `git lfs ls-files`；上传后在另一全新目录克隆并 `git lfs pull`，运行 `scripts/check_release.py`、`scripts/setup_envs.sh`、管线测试及 WBS/WHS 全流程、VirtualCellTool 的 `tests_api.py` 和浏览器测试；确认输出与本轮报告一致，再对**每一个**外部旧目录做独立文件/校验和比对。第 1–3 项只能逐项评估，不能以“项目能运行”替代“旧目录没有独有资料”的证明。

`07_independent_reproduction_20260916/`（旧隔离核验副本）和 `08_gitlab_export/`（本轮发布副本）也占用大量空间，均被 `.gitignore` 排除。**08 在完成上传与新克隆前须保留**；07 是历史核验证据，是否保留由你在新克隆验收后决定。本轮没有删除任何文件。
