管线 ↔︎ VirtualCellTool 融合手册：按 iGEM DBTL 执行

当前入口修正（2026-09-25）：本文是历史整合方案，未表示项目合并或 CNV 开发已获授权。旧版 src.consensus 已删除；现行操作见管线阅读页，CNV 暂缓原因与 DBTL 候选方向见决策说明。

对应您的文档：《微缺失病计算通路复盘报告》（五步通路）· tools/VirtualCellTool/ · 03_pipeline/ 目标：把 L1 遗传证据管线接入 VCT 平台，形成可审计的 DBTL（Design–Build–Test–Learn）双循环。

Cycle-0：先有验收标准、再动工程

您已经为 VCT 立过 AC1–AC4。融合前，把同一套标准扩展到 L1：

建议 AC 补充（新增）： - AC-L1-1（ClinGen 连接率）：输入的候选基因中，能连接 ClinGen 的比例 ≥ 60%（未覆盖的不罚，但写 audit） - AC-L1-2（正对照通过）：TBX1/ELN/KCTD13/RAI1（文献锚定主效基因） 在 consensus 排名前 10% 或 ClinGen HI score ≥ 2 - AC-L1-3（审计完备）：每次运行都生成 outputs/audit/run.json + data_checksums.txt，包括数据源 MD5、输入 gene 数、连接率、缺失率 - AC-L1-4（HPA 阈值稳定）：器官过滤阈值与 L1 重复排序两次稳定（deterministic）

这套 AC 把”负结果可报告”直接设计为判据之一。

Cycle-1：Design — 决策框架

  1. 决定 L1 扮演角色：我们未来的 VCT 有两个功能——候选源选择 + （CellOracle）扰动后检验。决定 L1 生成“遗传学等级”，VCT 生成“机制假设”，决定排库方子的“正对照”（TBX1/ELN/KCTD13/RAI1）事先测试。
  2. 决策方式：docs/decisions/ADR-002-l1-in-vct.md（在输出骨架里加入这个文件）。比如：“决定用 weighted_vote（见 config/pipeline.yaml）”、“决定 missing_handling=neutral（让不覆盖的 ClinGen gene 不扣0）”。
  3. Data Contract：定好输入/输出 schema（已在工程指导书 §3.2/§3.4 名列），让 L1 和 VCT 之间只交换 CSV/Parquet，避免直接传递模型。

Cycle-3：Test — 验收测试（独立手写测试）

  • Load test（AC-L1-3 审计）：tests/test_audit.py 复查 run.json + data_checksums.txt

  • 正对照 comparator：tests/test_positive_controls.py 过一个测试，读取 candidates 里 expected=True 的 rank 中位数，并断言 AC-L1-2

每次并入必须至少有一个正对照（如 TBX1），否则报告拒绝。

Cycle-4：Learn — 决策依据

  4. 同步：把 Learn 得到的结果写入 VCT 的 WORKLOG 和点评你的复盘报告静候option

集成方案：L1 遗传学证据层与 VirtualCellTool 的融合

配套：工程化指导书_微缺失主效基因筛选管线.md · PROJECT_PROGRESS_REPORT · EXPERIMENTS_EXPLAINED 核心判断：您的负结果（归因≠因果、删失基因 mRNA”隐身”、GEARS 结构性死路）恰好切断的是”计算筛选”这条死路；而您报告第四章明确提出的”证据金字塔”（L1 遗传 → L2 Perturb-seq → L3 虚拟扰动）缺少可运行的 L1 层——本文档就是 L1 层的实现，并设计好与 VCT/SIGnature 的接口。

一、为什么这个管线正好补上您的缺口

您的 11 个实验（E1–E11）得出了三条结构性天花板，每一条都对应本管线的设计动机：

您的天花板（复盘报告） 本管线对应解决方式
E3/E4：归因是表征敏感性（≈DE），预测不了因果（r=0.02） 本管线不依赖转录组：ClinGen 人工评级 + pLI/LOEUF 群体约束是完全独立的证据源（L1）
E6/E8：删失基因在稳态 mRNA 中”隐身”（GTF2I Δattr≈0、TBX1 脑不表达） 在基因层排序，不依赖表达量：LOEUF 直接量化群体中选择压的强弱，与单细胞可靠性脱钩
E11：GEARS/偏扰训练图缺失主效基因（4/41） ClinGen 人工评级与深度无监督模型（DeepLOF/DosaCNV）可评估任意基因，不要求共表达图覆盖
正负结果转化：两条独立线（SIGnature + CellOracle）收敛到同一批候选 本管线是 L1 的正面候选集；VCT 从 L3 输出时能通过预注册的正对照（TBX1/RAI1/ELN/GTF2I）作方法学验证
E6 pivot：TBX1 在脑类器官不表达（0.16%）→ 选病困难 本管线在 L1 里加 HPA 器官表达过滤——一个基因要在”目标组织可扰”才进入下游，从源头上避免 E6 型 pivot
报告结尾：“靶点用文献确证结论定，不再依赖计算筛选” 本管线允许你同时执行文献锚定（正对照）与系统排名，两者互相验证

二、架构：您的证据金字塔（L1/L2/L3）怎么走通

原报告里这个金字塔只有概念层。集成后，每一层都有明确的工具与产出：

L1 人类遗传学剂量证据
   ↓（本管线）
   ClinGen score + pLI/LOEUF + HPA organ filter
   03_pipeline → candidates_ranked.csv
   ↓
L2 真实 Perturb-seq（可选加强）
   ↓（您未来可以补上；当前暂用文献替代）
   真实敲低/表达数据（如有）
   ↓
L3 虚拟扰动机制假设
   ↓（您已有 VirtualCellTool）
   SIGnature + SCimilarity + CellOracle（机制假设/负结果报告）
   ↓
报告：药物线按文献锚定 + 计算线作为框架证据贡献
   （A/B 解耦，与您报告 4.2 的新策略对齐）

三、具体集成接口（三个接入点）

接入点 1：L1 管道 → VCT（正向输入）

您的 VirtualCellTool 当前的候选源是差异归因（Δattr）与 DE。现引入 L1：用本管线的 03_pipeline/outputs/wbs/candidates_ranked_v2.csv（或任一 mode 排名 outputs/mode/ranked_*.csv） 作为 VCT 的候选生成器输入。

  • 具体操作：在 VCT 的候选选择 UI 里加一个 “L1 genetics ranking” 数据源选项；点击后按 consensus_score 排序，拿 top-N 进入 CellOracle 的 GTF2I 扰动或 SIGnature 的归因刻画。
  • 结果形式：VCT 报告里明确标注”该候选来自 L1 遗传学，而非纯表达”；E3/E4 负结果保留，但语义转为”我们排除了不靠 L1 全靠归因的路径”。

接入点 2：您已知的 41 基因 + 正对照（方法学验证）

您报告 4.2 提到过”用 RAI1/ELN/TBX1 已知答案做方法学正对照”。本管线直接实现这一做法：

  • 把您 8 种病的 41 个候选基因列表放入 input/candidates.csv（合并贴一个 disease 标记列）
  • 运行 L1 管道 → 检查哪些已知主效基因（TBX1、ELN、KCTD13、RAI1、GTF2I、COMT 等）排在前列
  • 若前排名次集中在您的文献锚定基因上 → L1 框架有效；若不匹配，把这个负结果直接写入报告（与您的风格一致）

接入点 3：VCT/L3 结果反向注释 L1 排名

您已经产出 Williams 的 NEUROD2/6/SOX5/NFIA/ZEB2/BCL11B 这批交叉验证基因。这个集合可用来测试 L1 + L3 的多视角排名：

  • 在 L1 管道里输入这 6 个基因 + 41 个正对照
  • 查看它们在 L1 共识中的实际位置（top vs tail）
  • 把 L3 收敛结果与 L1 的输出并排对齐成表格写进报告——这证明 L3 机制假设的收敛不是纯巧合，也与 L1 信息一致。

六、长期的发展方向（可选）

  • 如果 L1 层稳定运行，您可以继续拨正 prescore：把 DeepLOF/DosaCNV 作为可选 CSV 上传，纳入 consensus（但仍以 ClinGen/pLI 为主）
  • 利用 VCT 已有的机制假设输出（CellOracle GTF2I 全局≈0，Top方向正确）在报告里明示：“L1 候选是提名，L3 只是机制假设——不是因果验证”
  • 若你们在某一条微缺失病有真实 Perturb-seq（如 16p11.2 在 K562 有单基因敲低），可以跑 L2 层实测，比较 L1 排名与 L2 实验的相关性来最终定标

七、争议/考量

  • ClinGen 人工评级覆盖不全：部分候选 ClinGen 未评级（Hi=NaN），pipeline 对 missing 做 neutral（score=0）——请调查报告当中 “缺失比例”，不隐藏
  • pLI/LOEUF 的 α-阈值选择：课题组共识你们用 v2 （阈值 0.35）或 v4（阈值 0.6）；我们建议 v2 保真，你们可以改 config
  • HPA 器官过滤：基于 mRNA 表达，是独立于归因/DE 的另一个证据源，权重为负（高器官表达 → 降权）；在报告中说明该阈值为可配置的测试性选择
  • 正对照选择：TBX1/ELN/KCTD13/RAI1 是文献中商讨过的主效基因；部分（如 GTF2I）在 Williams 中是多个候选之一，而 UBE3A 的印迹修复更难——属于”灵活控件，管理难度较高”
