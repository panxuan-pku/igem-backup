# iGEM SINEUP 微缺失主效基因筛选管线 —— 工程化指导书

**版本**：v1.0 · **生成时间**：2025-09-01  
**目标**：将“几十个基因 → 精准排序”的人工筛选过程工程化，成为可重复、可审计、可扩展的团队管线。

---

## 1. 项目愿景与范围

- **输入**：一个或多个微缺失区间的候选基因列表（HGNC 基因符号，每行一个，从 BED/VCF/Symblex-V 或直接由 DECIPHER 导出，也可手动维护 CSV）。
- **输出**：按 consensus 排序的 top-N 推荐清单，附带每一级的证据等级、ClinGen 评分、pLI/LOEUF、组织表达过滤，及供 SINEUP/AAV 设计选择的标注（如 short-gene / tissue-specific / liver-risk）。
- **设计原则**：非侵入于团队既有流程；核心是“join + score + rank”，把外部数据源对齐到 HGNC symbol。所有 AI/ML 打分以“预计算”或“推荐接口”形式接入，工程上不耦合具体模型，便于升级。

## 2. 总体架构

```

│  输入                                                           │

│           ↓                                                     │
│  ┌───────────────────────────┐                                  │
│  │ Module 0: 归一化 & 校验  │  resolve HGNC symbols → HGNC ID   │
│  └───────────────────────────┘                                  │
│           ↓                                                     │
│  ┌───────────────────────────┐                                  │
│  │ Module 1: 证据层整合       │  join ClinGen（❗人工金标准）    │
│  │                          │  gnomAD pLI / LOEUF（非AI约束）   │
│  │                          │  HPA organ expression（肝毒性）   │
│  └───────────────────────────┘                                  │
│           ↓                                                     │
│  ┌───────────────────────────┐   可选扩展（预计算或插件式）     │
│  │ Module 2: 预测层          │   DeepLOF/DosaCNV/DeepGenePrior   │
│  └───────────────────────────┘                                  │
│           ↓                                                     │
│  ┌───────────────────────────┐                                  │
│  │ Module 3: 共识排序        │  consensus score & 投票整合      │
│  └───────────────────────────┘                                  │
│           ↓                                                     │

└─────────────────────────────────────────────────────────────────┘
```

> “低耦合设计”背后的理由：让 ClinGen/约束分数先落地（可不用联网也可完全内置），AI 方法被设计成“可选预计算结果”或“环境依赖的可选模块”，保持 pipeline 可运行而可演进。sdflo

## 3. 数据规范

### 3.1 主键
- **主键**：HGNC ID（稳定、不可变）  
- **展示**：HGNC symbol（gene symbol）
- 输入里任何别名要先映射到 HGNC symbol（入库时要做别名字典，可用 HGNC custom downloads 官方别名表）

### 3.2 输入 file: `candidates.csv`
只需一次性提供，列：`gene_symbol`（或另列 `source`, `deletion_id`）。  
- **格式验证**：UTF-8，逗号分隔，必需列存在；空行删除；引号可选。
- **最小规模**：≥ 5 genes；推荐 20–100 genes。

### 3.3 数据源（核心 — 已验证为稳定）
| 数据 | 下载来源（已验证） | 用途 | 是否内置 |
|------|-------------------|------|---------|
| ClinGen Dosage Sensitivity curation | `https://ftp.clinicalgenome.org/`（具体任一 `ClinGen_gene_curation_list_GRCh38.tsv`） | 人工金标准 | **内置必装** |
| gnomAD constraint (pLI, LOEUF) | Downloads 区（gnomad.broadinstitute.org/help/constraint；也可 UCSC track 导出） | 非AI约束基线 | **内置** |
| Human Protein Atlas RNA expression | `https://www.proteinatlas.org/about/download` → `rna_expression_consensus.tsv` | 肝/器官毒性过滤（AAV） | **内置** |
| HGNC gene symbol / aliases | HGNC Custom Downloads | symbol normalization | **内置** |
| DECIPHER（可选扩展） | DECIPHER web（表格式下载需要账号；仅用作研究级别） | phenotype context | 可选 |
| DeepLOF / DosaCNV / DeepGenePrior | 接口有示例接口定义，但不预装依赖 | AI layer（可选） | **可选外部服务** |

> ⚠️ 说明：HPA 的“rna_expression_consensus.tsv”包含 51 consensus tissues（v23，样本数为 19297 genes）— 检出列表（“Liver”, “Brain”, “Kidney”, “Gastrointestinal”）微有偏移，但用内置的过滤（`tissue in ("liver","brain","kidney","gastrointest")`）保持简单即可。

### 3.4 中间结果 schema（`evidence.parquet`）
- **一张长表**：多行每 gene，列包括
  - `hgnc_id`, `gene_symbol`, `clinGen_hi_score` (0|1|2|3|NaN), `clinGen_triplo_score`(同),
  - `gnomad_pLI`（可缺）、`gnomad_LOEUF`（可缺）、`hpa_liver_expr`、`hpa_brain_expr`、`hpa_kidney_expr`、`hpa_gi_expr`
  - `microlength`（可选，mRNA 长度，用于 SINEUP 载体容量评估）
  - 每台 AI 预计算：`deeplof_score`, `dosacnv_score`, `deepgeneprior_score`（均默认 NaN）

存储建议：Parquet（压缩去重），但每人可换 CSV 也可以。

## 5. 配置文件样例（`config/pipeline.yaml`）

```yaml
# —— 约束分数阈值（非AI）
gene_constraints:
  pLI_threshold: 0.9          # pLI > 0.9 视为 HI-suspect
  LOEUF_upper: 0.35           # LOEUF < 0.35（v2）/ < 0.6（v4）
  use_LOEUF_v4: true           # 团队约定用 v4 threshold

# —— ClinGen 强化加权
clinGen:
  weight_hi: 3                 # score ∈ [0,3]；weight 用于 consensus
  use_score: haploinsufficiency

# —— HPA 器官毒性过滤（AAV 敏感性）
hpa_filter:
  organs: ["liver", "brain", "kidney", "gastrointestinal"]
  high_expression_log: 1.0     # 可微调；默认从 TP1 100 TPM log1p 阈值
  negative_expr_threshold: 4.0 # 负分数：高表达的过滤逻辑

# —— 共识排序权重（见 Module 3）
consensus:
  base_weights:
    clinGen_hi_score: 3
    gnomad_LOEUF: 2            # 只在一个 direction（LOEUF↓）入账
    gnomad_pLI: 2
    DeepLOF_score: 3
    DosaCNV_score: 3
    DeepGenePrior_score: 2
    negative_hpa_organ: -2
  ranking_method: "weighted_vote" # 或 "borda" / "top_counts"
  missing_handling: "neutral"      # 缺数据等于 0，不罚

# —— 外部服务（可选；空则忽略）
external:
  api_endpoints: {}
  cache_dir: .cache/

# —— 数据校验（决定是否运行）
validation:
  max_missing_rate: 0.5            # 任何 source 中竟超过 50% 就 fail
  require_unique_hgnc: true        # 每行必需唯一 HGNC ID
```

## 6. 关键模块设计

### 6.1 Module 0：`normalize.py`
- **职责**：输入候选 → 输出标准 HGNC ID。  
- **实现**：从 HGNC 别名表（hgnc_aliases.tsv）构建 dict {prev/names → HGNC ID}，然后忽名匹配与 previous symbol 匹配；失败的基因 log 到 audit。
- **产出**：`normalized.csv`（含 `hgnc_id`, `input_symbol`, `status`(ok|alias|previous|unresolved)）。
- **质量**：若 > 10% unresolved，报错 fail（看 log）。

### 6.2 Module 1：`merge_evidence.py`
- **职责**：将 normalized gene list join 到 ClinGen + gnomAD + HPA 表，输出 `evidence.parquet`。  
- **关键做法**：ClinGen/gnomAD/HPA 都先单独 indexed by HGNC ID，然后 `large join`；缺失填 NaN，权重的配置从 `pipeline.yaml` 读。
- **verify**：每个数据源要有 checksum 记录；连接比例要与 candidates size 记录（连接率 < 100% 无问题，但 host 会有 log）。
- **产出**：`outputs/evidence.parquet` + `outputs/audit/data_checksums.txt`

### 6.3 Module 2：`prescore.py`（可选 AI 预计算/扩展）
- **职责**：生成 AI 分数（DoseCNV / DeepLOF / DeepGenePrior）。
  - **推荐方式**：独立脚本/服务运行式，把 AI 运行结果输出为一个 CSV：`ai_scores.csv`，列：`hgnc_id`,`DeepLOF_score`,`DosaCNV_score`,`DeepGenePrior_score`；然后在 pipeline 里只做 join。
  - **接口契约**（详细见 docs/api）：温度不固定，每次新模型重跑所有基因。
- **产出**：`outputs/ai_scores.csv`（若未运行，为 None，不 fail）。

### 6.4 Module 3：`consensus.py`
- **职责**：把所有证据汇成单一 ranked list，输出 `candidates_ranked.csv` + `report.md`。  
- **算法**（复杂可自定义）：`weighted_vote`
  - 对每个证据，根据配置权重+ direction：
    - LOEUF ↓，pLI ↑ 的 gene 记 +weight；如果有缺失记 0；负向 hpa_organ 高表达记 −weight。
  - 得出 `consensus_score`，然后 sort descending、公布前 N（如 top 10）。
  - **决定**：只在“正样本 ≥ 1”提交时才公布；避免缺少数据时忘记。
- **可审计性**：在 report.md 里保留每个 gene 的“投票”分项表格，及谁对哪个权重。这样议 does the test 固定。

### 6.5 报告（`report.py`）
- **形式**：每 run 生成 `outputs/report.md`（花园式 snapshot）可读
- **必须包含**：
  - run 元数据：run id、日期、输入 gene 数、完成 join 的百分比
  - 10 行候选 table（gene symbol、最终排名、几个关键证据）
  - 每个证据分数的加权和（贡献表）
  - 数据校验警告（某 source 连接率、基因名 unresolved 列表）
- **建议**：同时输出 `candidates_ranked.csv` 的完整全量文件（CSV，UTF-8）。

## 7. 可行路径与验收门槛

### 7.1 里程碑
| 里程碑 | 已完成判据 | 目的 |
|--------|------------|------|
| M0 | candidates.csv 转 normalized.csv，≥90% 正确 HGNC ID | 归一化可行 |
| M1 | evidence.parquet 生成，src 接口文件可 checksum | 数据对齐合格 |
| M2 | 有 clinGen/pLI/LOEUF/HPA join 字段，evidence 有 audit | 证据层稳定 |
| M3 | candidates_ranked.csv + report.md 自动生成 | 容许放行 |
| M4 | 小组评审（technique + 伦理）通过，签署决策 | 发布到实验阶段 |

### 7.2 数据质量工位（GIT/ci）
- **属性测试**（快速试）：normalize 输入 a few known symbols → 应得 HGNC ID；若不能 → pipeline fail。
- **模式属性**：所有 fabricate 的 `hgnc_id` 都应在 ClinGen/gnomAD 连接后 **被保持**；若某 source 缺失则 log；
- **处理-顺序的排序稳定性**：run consensus 两次，结果应该相同（默认和 stable sort）。
- **审计输出**：每 run 输出 `audit/run.json` 列：times、input、缺失比例、使用数据文件 MD5。

### 7.3 交付前检查清单（team）
- [ ] `evidence.parquet` 已经存在，**覆盖** `hgnc_id` 到 `clinGen_hi_score` join；即 conn rate 已计算

- [ ] `report.md` 包含：每基因的加权投票细目； ClinGen / pLI 的统一截图
- [ ] 若使用 AI：docs/api 中有被约定的方式preserve
- [ ] 数据 checksums 数据已commit/repository 里 mobile 遗失不可能

## 8. 安装与启动（本机/服务器）

选择 uv（推荐，与沙盒一致）或 conda。

```bash
# uv 方案
cd gene_prioritization_pipeline
uv init --python 3.11
uv add pandas pyarrow pyyaml numpy scipy requests
```

或 conda `environment.yml`：

```yaml
name: igem-gene-pipeline
channels: [conda-forge]
dependencies:
  - python=3.11
  - pandas
  - pyarrow
  - pyyaml
  - numpy
  - scipy
  - requests
```

**启动一次运行**（推荐一个端点）：

```bash
python -m src.normalize \
  --input input/candidates.csv \
  --out data/normalized.csv \
  --hgnc-alias data/hgnc_aliases.tsv
python -m src.merge_evidence \
  --normalized data/normalized.csv \
  --config config/pipeline.yaml \
  --out outputs/evidence.parquet \
  --audit outputs/audit
python -m src.consensus \
  --evidence outputs/evidence.parquet \
  --ai-scores outputs/ai_scores.csv \
  --config config/pipeline.yaml \
  --out outputs/candidates_ranked.csv \
  --report outputs/report.md
```

## 9. 团队运行约定

1. **只修改 config 不改代码**——所有阈值（pLI/LOEUF/HPA）从 `config/pipeline.yaml` 集中。
2. **数据源 dummy files**——数据不寄 git，但在 `data/` 提供 `sources.json` + 预期的 checksum；图例见模板。
3. **每次 run 留 metadata**——audit/run.json 记录，供决定追溯。
4. **分布式/重复性**：每次逐笔运行 update evidence 新生产；cache 不选用 public。
5. **AI 扩展的边界**——prescore 模块可选跑，跑不跑不影响 pipeline 流程。若为了对照在团队内部，把 AI 准备为一个 summaries `ai_scores.csv`。

## 10. 风险与警示

- **不直接断定机制**：ClinGen/pLI / AI 只是提名；最终必须让小鼠/斑马鱼/细胞模型验证（22q11.2 TBX1/16p11.2 KCTD13 的经典方法）。其他为“证明上调 recover”才是答案。
- **标签偏倚**：HI 监督历史短暂，；HIPred、DeepGenePrior、DeepLOF 都强提醒了这种确证偏倚，请**不要**把 pLI/LOEUF/AI 当作真理。
- **预印本风险**：DosaCNV 是预印本（bioRxiv，在检索日），故把它当“实验性增强”，不应影响 team 的主流程的决策。

## 附录 — API 契约示例（`docs/api/ai_scores.md`）

管道对 AI 是“可弃”：
- **输入**（若运行 AI）：读取 `evidence.parquet`，让一个端口（可运行 DeepLOF/DosaCNV/DeepGenePrior）写出一个 CSV：`ai_scores.csv`。
- **契约**：
  - column: `hgnc_id`, `DeepLOF_score`, `DosaCNV_score`, `DeepGenePrior_score`
  - 缺失为空，或者用 NaN
  - 每次从 pipeline 启动后读这个文件；当缺失时该基因在该 weight 中 = 0
- **说明**：任何应公司 microservice，可以在内部对 cache 进行 get/set，但从 pipeline 视角只读 CSV。pipeline 不负责实际模型的运行环境。
