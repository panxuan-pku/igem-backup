## 3. 模块详解

### 3.1 L0 归一化 ✅ `src/normalize.py`

**职责**：基因符号 → HGNC ID 主键解析。

```bash
python -m src.normalize --input input/candidates.csv --out data/normalized.csv \
    --hgnc-alias data/hgnc_aliases.tsv
```

**为什么必须由 HGNC ID 做主键**（ADR-001）：基因符号会变更与合并。实测案例——gnomAD 表中 NSD2 的数据以旧符号 **WHSC1** 存储，按符号精确匹配会静默丢弃最强约束证据（见 §7.1）。

**别名表覆盖**：`prev_symbol` / `alias_symbol` 均参与解析（实测 18651/19704 条解析成功）。

### 3.2 L1 证据层 ✅ `src/merge_evidence.py`

**职责**：把三个外部数据源合并到候选表上，输出 `evidence.parquet`。

| 数据源 | 关键列 | 合并键 | 说明 |
|---|---|---|---|
| ClinGen gene curation | `clinGen_hi_score`、`clinGen_triplo_score` | hgnc_id | **三值语义**：3=明确 HI；30=不确定；40=无证据。30/40 转中性不扣分 |
| gnomAD constraint | `gnomad_pLI`、`gnomad_LOEUF` | **先解析为 hgnc_id** | 保留原始列名映射（`pli`、`oe_lof_upper`）；v2.1.1 列名兼容 |
| HPA RNA consensus | `hpa_{organ}_expr` | hgnc_id | 宽表（Gene, Tissue, nTPM）→ pivot 成逐器官列 |

**实测输出形状**（WBS 35 基因）：`evidence_wbs_modeA.parquet` = 35 × 8 列
```
hgnc_id, input_symbol, clinGen_hi_score, clinGen_triplo_score,
gnomad_pLI, gnomad_LOEUF, hpa_liver_expr, hpa_kidney_expr
```

⚠️ **已知缺陷**：HPA 当前只 pivot 出 `liver` / `kidney` 两列（config 的 `hpa_filter.organs` 虽列了 brain/gastrointestinal，脑组织列名未进入映射）。这直接影响脑相关表型的靶组织可行性判断——B 组待修（见 §10）。

**审计**：每次运行写 `audit/run.json` + `data_checksums.txt`。

### 3.3 L2 AI 层 ⚠️ `src/ai_scores.py`

| 模型 | 状态 | 说明 |
|---|---|---|
| **DeepLOF** | ✅ 已接入 | 官方预计算分数 19,197 基因（CC BY 4.0）；实测覆盖 WBS 28/35 |
| DosaCNV | ❌ 未实现 | config 有权重项（`DosaCNV_score: 1`）但无实现代码 |
| DeepGenePrior | ❌ 未实现 | 同上（权重 1） |

⚠️ **DeepLOF 的已知盲区**：**GTF2I 不在 19,197 行评分中**——不是管线 bug，是 DeepLOF 训练时部分特征缺失被过滤。引用 DeepLOF 结果时需说明。

配置权重（`consensus_v2.evidence.*.weight`）：`DeepLOF_score: 1`（低权重，仅在遗传学证据弱时提供加成）。

### 3.4 L3 证据整合与排序 ✅ `src/consensus_v2.py`

**核心算法**：归一化 → 加权求和 → 排序，并附带 Borda 对照与多个可选的诊断/调优层。

```bash
python -m src.consensus_v2 \
    --evidence outputs/<主题>/evidence.parquet \
    --ai-scores outputs/ai_scores.csv \
    --config config/pipeline.yaml \
    --mode auto \
    --out outputs/<主题>/candidates_ranked_v2.csv \
    --report outputs/<主题>/report_v2.md
```

**证据源与权重**（`config/pipeline.yaml` → `consensus_v2.evidence`）

| 证据 | direction | weight | 归一化方式 |
|---|---|---|---|
| `clinGen_hi_score` | `ordinal`（scale=3，低分惩罚 0.5） | **3** | 序数映射 |
| `gnomad_LOEUF` | `lower_better` | 2 | 反向归一化 |
| `gnomad_pLI` | `higher_better` | 2 | 直接归一化 |
| `DeepLOF_score` | `higher_better` | 1 | 直接归一化 |
| `DosaCNV_score` | `higher_better` | 1 | ❌ 无数据源 |
| `DeepGenePrior_score` | `higher_better` | 1 | ❌ 无数据源 |

**归一化方法**：`normalize: raw`（✅ v2.2）。**不要改回 `rank`**——小样本下会产生伪影（§7.2）。

**Borda 对照**：并行计算 Borda 分数与排名，输出 `borda_score` / `borda_rank`，并算 Spearman ρ 作为"加性 vs Borda 是否一致"的诊断指标。

**停用项**：
- `hpa_penalty`：`cap: 0.0`、`per_organ_weight: 0.0`、`expr_threshold: 9999.0` —— 等效关闭。原因见 §7.3。

**可选层**（需显式开启）

| 功能 | 开关 | 作用 | 输出位置 |
|---|---|---|---|
| mRNA 补偿集成 | `--compensation comp.csv` | 合并 `compensation_class` 等列，并在报告中渲染补偿状态表 | CSV 列 + 报告 |
| 隐性基因惩罚 | config `recessive` + `df["recessive"]` 列 | 对隐性致病基因的 gnomAD 贡献乘 `gnomad_weight_multiplier`(0.5) | `meta.recessive_applied` |
| LOO 权重调优 | `--tune` 或 config `tuning.enabled` | 用已知正对照留一法搜权重 | `meta.tuning` |
| 权重敏感性 | `--sensitivity` | 每个证据权重 ±1，看排名位移与 Top3 变化 | `meta.sensitivity.robustness` |
| 稀疏性警告 | `--warnings`（auto/exploratory 自动开） | ClinGen 覆盖率低/分数差距小/零覆盖时警告 | `meta.warnings` → 报告 |

### 3.5 辅助模块

#### `src/compensation.py` — mRNA 补偿状态 ✅
```python
compute_compensation(adata, genes_of_interest, group_col="condition",
                     patient_cat="WS", ref_cat="CTRL",
                     layer="counts", min_detection_pct=0.01)
```
输出列：`gene, compensation_ratio, compensation_class, mean_patient, mean_reference, pct_patient, pct_reference, n_patient, n_reference`

分类阈值（config `compensation.thresholds`）：

| 类别 | ratio 区间 | 对 SINEUP 的含义 |
|---|---|---|
| `full` | 0.95–1.05 | ★ 理想——转录层已完全补偿，问题在翻译层，正是 SINEUP 的适用场景 |
| `partial_high` | 0.85–0.95 | ▲ 部分补偿 |
| `partial_low` | 0.70–0.85 | 部分补偿（较弱） |
| `uncompensated` | 0.40–0.70 | ✗ 未补偿——可能需要转录层干预而非翻译层 |
| `unreliable` | 表达过低不可判 | ? 无法判定 |

⚠️ `compensation.enabled: false`（默认关闭），必须显式传 `--compensation` 才生效。

#### `src/filter_recessive.py` — 隐性致病基因过滤 ✅
```bash
python -m src.filter_recessive --normalized data/normalized.csv \
    --hgnc-alias data/hgnc_aliases.tsv --omim <genemap2.txt> --clinvar <clinvar.tsv> \
    --out data/recessive_flags.csv
```
用途：识别 OMIM/ClinVar 标注的**隐性**致病基因，在 L3 中降低其 gnomAD 约束贡献——因为隐性致病基因的杂合携带者通常无症状，其 pLI/LOEUF 不耐受性不直接对应主效基因。

#### CNV 工作流 `src/cnv/` ✅（仅 Mode C 路径使用）

```bash
python -m src.cnv.workflow all --config config/cnv.yaml
```
阶段：`stage-samples`（整理 GEO 原始文件为 per-sample 10x 目录）→ `prepare-order`（基因排序）→ `infercnv` → `call-segments` → `extract-genes`。另有 `expression_qc.py` 做区间基因表达 QC。

**用途定位**：提供 scRNA-seq 侧的**验证信息**（表达 QC、组织特异性），**不用于自动发现缺失区间**——scRNA-seq CNV caller 对 <3 Mb focal CNV 灵敏度极低（Schmid et al. 2025）。

```
outputs/

├── audit/   数据校验和与运行记录

├── ai_scores.csv      DeepLOF 全基因分数
└── README.md          索引
```

### 5.2 排名 CSV 字段

| 字段 | 含义 | 读法要点 |
|---|---|---|
| `rank` | 最终排名 | — |
| `hgnc_id` / `input_symbol` | 主键 / 输入符号 | — |
| `clinGen_hi_score` | 单倍剂量不足评分 | 3=明确 HI；**30/40 = 不确定/无证据**（不是分数） |
| `clinGen_triplo_score` | 三倍剂量敏感性 | — |
| `gnomad_pLI` | 对 LOF 不耐受概率 | **高**才算剂量敏感 |
| `gnomad_LOEUF` | 观察/期望 LOF 比 | **低**才算剂量敏感（最常被读反的一对） |
| `hpa_*_expr` | HPA 组织表达 | 组织可行性参考 |
| `DeepLOF_score` | AI 层 LOF 不耐受 | 可选；GTF2I 等部分基因缺失 |
| `compensation_ratio` / `compensation_class` | 患者/对照 mRNA 比与分类 | 需 `--compensation` 才有值 |
| `consensus_score` | 加权总分 | 排序依据 |
| `contrib_*` | **各证据源贡献分解** | **排查"它凭什么排第一"看这几列** |
| `hpa_penalty` | 惩罚项 | 当前恒为 0 |
| `borda_score` / `borda_rank` | Borda 对照 | 与加性排名分歧大 → 提示权重敏感 |
| `mean_patient` / `mean_reference` / `pct_*` / `n_*` | 补偿分析的原始统计 | 判断 `unreliable` 时看 `n_` 与 `pct_` |

### 5.3 报告（`report_*.md`）
包含：模式标签、Top-N 表、**正对照检验表**（全 mode）、补偿状态表（若有）、验证面板（Mode A）、探索声明（Mode D）、稀疏性警告、实验建议（非 Mode D）。

## 6. 运行模式（实际行为）

| Mode | CLI 取值 | 正对照检验 | 稀疏警告 | 验证面板 | 实验建议 | 探索声明 |
|---|---|---|---|---|---|---|
| A 验证 | `validate` | ✅ | 仅 `--warnings` | ✅ | ✅ | — |
| B 增强筛选 | `rank` | ✅ | 仅 `--warnings` | — | ✅ | — |
| C 全栈筛选 | `full` | ✅ | 仅 `--warnings` | — | ✅ | — |
| D 探索 | `exploratory` | ✅（信息性） | ✅ 自动 | — | **❌ 不给** | ✅ |
| 自动 | `auto`（默认） | ✅ | ✅ 自动 | — | ✅ | — |

⚠️ **两点必须知道**：
1. **`auto` 不会自动解析成 A/B/C/D**。它的实际含义 = "正对照检验 + 稀疏警告"，是独立的一组行为，不是"数据丰富度自动检测"。v2.0 §2/§8 对此的描述与实现不符。
2. **Mode C（`full`）当前行为与 Mode B（`rank`）相同**——只有报告标签不同。补偿集成是靠 `--compensation` 参数启用的，**不由 mode 决定**。

### 使用示例

```bash
# Mode A（验证：已知主效基因，如 WHS 的 NSD2）
python -m src.consensus_v2 --evidence outputs/whs/evidence_whs_B.parquet \
    --config config/pipeline.yaml --mode validate \
    --controls input/controls_whs.txt \
    --out outputs/whs/candidates_ranked_whs_B.csv --report outputs/whs/report_whs_B.md

# Mode B（增强筛选：有正对照、要排序）
python -m src.consensus_v2 --evidence outputs/mode/evidence_wbs_modeA.parquet \
    --ai-scores outputs/ai_scores.csv --config config/pipeline.yaml --mode rank \
    --controls input/controls_wbs.txt --sensitivity \
    --out outputs/mode/ranked_wbs_modeB.csv --report outputs/mode/report_wbs_modeB.md

# Mode C（全栈：加补偿状态）
python -m src.consensus_v2 --evidence outputs/mode/evidence_wbs_modeA.parquet \
    --config config/pipeline.yaml --mode full \
    --compensation outputs/mode/compensation_wbs.csv \
    --out outputs/mode/ranked_wbs_modeC.csv --report outputs/mode/report_wbs_modeC.md

# Mode D（探索：无金标准，不给实验建议）
python -m src.consensus_v2 --evidence <novel>.parquet \
    --config config/pipeline.yaml --mode exploratory --warnings \
    --out outputs/novel/ranked.csv --report outputs/novel/report.md
```

## 9. 为什么机制层（L4）不能回补排序

L3 的输出单向流向 VirtualCellTool，机制预测结果**不回补 L1/L3 排序**。理由：

1. **信息源重叠**：回补等于用转录组数据二次加权转录组数据，重新引入项目已验证过的偏倚（归因与真实扰动效应 r=0.02）
2. **mRNA 隐身**：删失基因的稳态 mRNA 在转录层不可检测（E8），若允许回补，这类基因会被系统性低估
3. **可验证性**：L1 只依赖外部遗传学证据，任何人可独立复算；混入模型预测后不再可独立复核

机制层的定位是**生成假设与可视化演示**，不是裁决。

## 10. 已知限制与待办

### 10.1 数据层限制

| 限制 | 影响 | 缓解 |
|---|---|---|
| HPA 仅 liver/kidney 两器官 | 脑等靶组织可行性判断缺失 | 修 `merge_evidence` 的器官映射（**优先**） |
| ClinGen 对 WBS 覆盖率仅 14%（5/35） | 微缺失病的普遍问题：多数区间基因无人工评级 | 靠 gnomAD 约束 + 警告提示置信度 |
| DeepLOF 缺 GTF2I 等基因 | AI 层不完整 | 引用时说明；考虑补充替代模型 |
| WHS 无公开 scRNA-seq 数据 | 无法做补偿分析 | 依赖小鼠模型（GSE232564） |
| gnomAD 符号别名依赖别名表完整 | 表不全会再次静默丢证据 | 已修；建议加"匹配率过低"警告 |

### 10.2 方法层限制

| 限制 | 性质 |
|---|---|
| 单基因 vs 多基因错配 | 微缺失是连续基因综合征；单排名不应被读作"唯一因果基因"（已有警告） |
| 排名 ≠ 组织内效应量 | 实测 GTF2I 排名 #9 但在脑类器官中效应量第一（|Δ|max=10.08） |
| 翻译层盲区 | **根本性**——RNA 层证据无法预测 SINEUP 的翻译增强效果 |
| 权重来源缺依据 | config 中各证据权重多为经验取值，尚无文献/数据支撑依据 |

### 10.3 工程待办

| 项 | 优先级 |
