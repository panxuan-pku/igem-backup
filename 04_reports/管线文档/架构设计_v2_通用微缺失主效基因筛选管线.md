## 1. 设计原则变更

| # | v1 (2025-09) 隐含假设 | v2 (2026-09) 设计原则 |
|---|---|---|
| 1 | scRNA-seq 是前提条件 | scRNA-seq 是**可选增强层** |
| 2 | 所有基因混排一个排名 | **按表型分组**，组内排序 |
| 3 | 管线输出"唯一的正确排序" | 输出**证据分层**：确认 → 推测 → 探索性 |
| 4 | 管线只处理 WS 一种病 | 通用架构，适应从 WHS 到全新 CNV 的全谱系 |
| 5 | CNV 工作流单独存在 | 基因提取独立化：缺失区间坐标 + GTF → 基因列表（**无 scRNA-seq 依赖**） |

## 4. 核心模块设计

### 4.1 Module A: 区间基因提取（独立入口，不依赖 scRNA-seq）

**职责**：从缺失区间坐标直接产出基因列表

```
输入: 缺失区间坐标 (chr, start, end, genome_build)
      + GENCODE GTF 注释文件
      + 已知主效基因列表（可选）
      + 已知表型映射（可选，HPO/OMIM ID）

输出: candidates.csv
  列: hgnc_id, symbol, source (known_interval|known_driver|auto_segment),
       deletion_id, associated_phenotype (若有)

验证: 区间坐标与 GTF 基因组版本一致
      区间基因数 ≥ 1
      已知主效基因都在区间内（若有）
```

**入口**（新增 CLI 子命令）：

```bash
# Mode A: 仅区间坐标
python -m src.extract_genes \
  --intervals config/intervals.yaml \
  --gtf data/gencode.v44.basic.annotation.gtf.gz \
  --out input/candidates.csv

# Mode A + 已知主效基因
python -m src.extract_genes \
  --intervals config/intervals.yaml \
  --gtf data/gencode.v44.basic.annotation.gtf.gz \
  --known-drivers config/known_drivers.yaml \
  --out input/candidates.csv

# Mode C: 区间坐标 + scRNA-seq 增强（现有 extract-genes 的升级版）
python -m src.extract_genes \
  --intervals config/intervals.yaml \
  --gtf data/gencode.v44.basic.annotation.gtf.gz \
  --scrna-h5ad outputs/cnv/cnv_input.h5ad \
  --out input/candidates.csv
```

**配置文件示例**（`config/intervals.yaml`）：


### 4.2 L1: 证据层（保持，增强 HPA 多组织逻辑）

**职责**：ClinGen + gnomAD + HPA 多组织表达 → evidence.parquet

**v2 增强**：HPA 从"惩罚层"改为"双重角色"

```yaml
hpa_config:
  # 角色1: 靶组织可行性 (正向信号)
  target_tissues:
    brain: {weight: +1, label: "脑表型可行性"}
    cardiovascular: {weight: +1, label: "心血管表型可行性"}
    neuromuscular: {weight: +1, label: "神经肌肉表型可行性"}

  # 角色2: 非靶器官安全性警告 (负向标记，不扣分)
  safety_organs:
    liver: {threshold_log: 2.0, label: "⚠️ 肝脏表达: AAV 脱靶风险"}
    kidney: {threshold_log: 2.0, label: "⚠️ 肾脏表达: AAV 脱靶风险"}

  # 全局安全门: 基因在 ALL 组织中都不表达 → 直接标记 "no_expression"
  global_min_expr_threshold: 0.5
```

**改动**：HPA 不再在 L3 consensus 中扣分。改为在 L1 阶段为每个基因标注：
- `hpa_target_support`: 在靶组织中有表达 → "supported" / "not_detected" / "unknown"
- `hpa_safety_flag`: 在安全性器官中高表达 → "clean" / "warning" / "critical"

### 4.4 L3: 多维度证据整合（重新设计）

**v2 不再产出单一的 consensus_score 排名。** 改为**五维证据面板**：

| 维度 | 内容 | 数据来源 | 对最终输出的贡献 |
|---|---|---|---|
| **遗传学剂量敏感性** | ClinGen HI 评级 + gnomAD pLI/LOEUF | 内置 | 核心排序依据 |
| **表达可行性** | HPA 靶组织表达 + scRNA-seq QC（若有）| 内置 + 可选 | 硬过滤（不表达=排除） |
| **安全性** | HPA 非靶器官表达 + 基因长度 + 已知毒性 | 内置 + 文献 | 安全标记（不扣分，但必须有） |
| **AI 预测** | DeepLOF 等 LOF 不耐受评分 | 可选 | 软加权（低权重，仅在遗传学证据弱时加成） |
| **文献/表型关联** | HPO/OMIM/ClinGen 已知表型映射 | 内置 | 表型分组依据，不直接加权 |

**输出格式变更**：

**v1 输出**：
```
rank | gene   | consensus_score | pLI   | ...
1    | FZD9   | 2.34            | 0.002 | ...
```

**v2 输出**：
```
### 神经发育表型
| rank | gene   | 剂量敏感性 | 表达可行性 | 安全性 | AI 支持 | 证据等级 |
|------|--------|-----------|-----------|--------|---------|---------|
| 1    | NSD2   | 🟢 HI=3, pLI=1.0 | 🟢 brain=15 TPM | clean | na | ★★★ 确认 |
| 2    | NELFA  | 🟡 pLI=0.7 | 🟡 brain=8 TPM | clean | na | ★★☆ 推测 |

### 心血管表型
| rank | gene   | 剂量敏感性 | 表达可行性 | 安全性 | AI 支持 | 证据等级 |
|------|--------|-----------|-----------|--------|---------|---------|
| 1    | ELN    | 🟢 ClinGen HI=3 | 🟡 cardio=5 TPM | ⚠️ liver | na | ★★★ 确认 |

### 未知/探索性
| rank | gene   | ... |
|------|--------|-----|
| ...
```

**证据等级定义**：

| 等级 | 含义 | 条件 |
|---|---|---|
| ★★★ 确认 | 高置信主效基因 | ≥1 人工金标准确认（ClinGen HI ≥ 2 或文献共识）+ gnomAD 强约束 + 靶组织表达 |
| ★★☆ 推测 | 有证据但未确认 | gnomAD 强约束 + 靶组织表达，但无人工确认 |
| ★☆☆ 探索性 | 弱证据 | 仅一项证据或纯 AI 预测 |
| ⚠️ 需验证 | 有争议 | 文献矛盾或无 gnomAD 覆盖 |

### 4.5 表型分组（新增维度）

**职责**：根据 HPO/ClinGen/OMIM 关联，将基因按疾病表型分组，组内独立排序

**实现**：`config/intervals.yaml` 中每区间注册已知 HPO 表型 → 基因层面从 ClinGen/HPO 映射补充

**意义**：
- ELN（心血管）和 GTF2I（神经）不在同一框架下比较
- NSD2（多系统多效）会出现在"神经发育"和"生长"两个表型组中，标记为"多效基因"
- 用户根据自己关注的具体表型，选择对应的组阅读

## 6. 四种模式的使用路径

### Mode A: 验证模式（WHS/NSD2 型）

```bash
# 输入: 区间 + 已知主效基因
python -m src.extract_genes \
  --intervals config/intervals.yaml --disease whs_4p16.3 \
  --gtf data/gencode.v44.basic.annotation.gtf.gz \
  --out input/candidates.csv

python -m src.normalize --input input/candidates.csv ...
python -m src.merge_evidence --normalized data/normalized.csv ...
python -m src.consensus_v2 --evidence outputs/evidence.parquet \
  --mode validate --known-drivers NSD2 ...
```

**输出**：验证报告（非排名）
- NSD2 的 ClinGen HI 评级、gnomAD 约束、HPA 脑表达、安全性、文献引用
- 区间其他基因的一览表（为何 NSD2 优于其他）
- 结论：NSD2 满足 SINEUP 靶向条件 ✓

### Mode B: 增强筛选模式（22q11.2 型）

```bash
python -m src.consensus_v2 --evidence outputs/evidence.parquet \
  --mode rank --positive-controls TBX1,COMT,PRODH ...
```

**输出**：排序 + 正对照验证
- TBX1 在排序中的位置 + 是否在 top-N
- 候选基因列表，标注证据来源

### Mode C: 全栈筛选模式（WS 型）

```bash
# 完整流程：CNV + 表达QC + 排序
python -m src.cnv.workflow all --config config/cnv.yaml
python -m src.consensus_v2 --evidence outputs/evidence.parquet \
  --mode full --scrna-qc outputs/cnv/interval_gene_expression_qc.csv \
  --positive-controls ELN,GTF2I,LIMK1,BAZ1B
```

**输出**：分层排序 + 表型分组

### Mode D: 探索模式（全新 CNV/未知区间）

```bash
python -m src.extract_genes \
  --intervals config/intervals.yaml --disease novel_cnv \
  --gtf data/gencode.v44.basic.annotation.gtf.gz \
  --out input/candidates.csv
python -m src.consensus_v2 --evidence outputs/evidence.parquet \
  --mode exploratory
```

**输出**：粗筛
- 所有基因行的 gnomAD 约束分数 + HPA 组织表达
- 标注："置信度低——以下为最可能候选，建议补充文献/实验验证"
- 不产出确定排名
